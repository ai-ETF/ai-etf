# 决策框架

## 概述

当用户问"我该怎么买"时，不直接给答案，而是提供决策框架，让用户自己填参数、自己得出结论。

**核心原则**：
1. 框架是工具，不是答案
2. 参数由用户自己填
3. 结论由用户自己得出
4. 最后问一句"你打算怎么做？"，让用户自己说出来

## 四种决策框架

根据用户的问题类型，选择对应的框架：

| 用户问 | 框架 |
|--------|------|
| 买多少 | 仓位管理框架 |
| 现在买还是等等 | 入场时机判断框架 |
| 一次性还是分批 | 定投vs一次性框架 |
| 选哪个标的 | 选择决策矩阵 |

---

## 1. 仓位管理框架

**触发**：用户问"买多少"、"仓位怎么配"

### 框架内容

> "仓位管理有几个原则："
>
> "- 单一行业不超过总仓位的 **10-20%**"
> "- 新开仓位建议先投计划的 **20-30%** 作为底仓"
> "- 保留至少 **X%** 现金应对意外"
>
> "结合你之前说的（总仓位约{用户回答}%，单行业上限{用户回答}%），你打算给{标的}分配多少仓位？"

### 引导问题

> "你打算给{行业}板块分配总资金的百分之多少？"

### 记录

```json
{
  "position_decision": {
    "target": "消费50",
    "position_size": "10%",
    "reason": "结合用户风险承受和仓位上限"
  }
}
```

## 2. 入场时机判断框架

**触发**：用户问"现在买还是等等"、"是不是底部"

### 框架内容

> "入场时机没有标准答案，但可以看几个信号："

| 信号 | 当前状态 | 判断 |
|------|----------|------|
| 估值处于历史低位 | {数据填充} | 由数据填充 |
| 资金流出开始放缓 | {数据填充} | 由数据填充 |
| 基本面出现拐点信号 | {数据填充} | 由数据填充 |
| 政策催化剂出现 | {数据填充} | 由数据填充 |
| 市场情绪从悲观转向中性 | {数据填充} | 由数据填充 |

> "- 满足 **3条以上** → 可以考虑入场"
> "- 满足 **5条** → 入场信号更强"
> "- 满足 **不到3条** → 可以再等等"

### 引导问题

> "根据这个框架，你想等更多信号确认，还是愿意左侧提前布局？"

### 记录

```json
{
  "timing_decision": {
    "signals_met": 3,
    "choice": "立即建底仓30%",
    "reason": "估值低+政策催化，但基本面未确认"
  }
}
```

## 3. 定投vs一次性框架

**触发**：用户问"一次性买还是分批"、"怎么建仓"

### 框架内容

> "两种方式各有适用场景："

| 方式 | 适合的情况 | 不适合的情况 |
|------|-----------|-------------|
| 一次性 | 确信是底部、不想踏空 | 担心继续跌、心理承受力弱 |
| 分批定投 | 不确定底部、想摊薄成本 | 急于建仓、怕踏空 |

> "结合你之前说的（投资期限{用户回答}，风险承受{用户回答}），"

### 引导问题

> "你更倾向于哪种方式？"

### 记录

```json
{
  "method_decision": {
    "method": "分批定投",
    "reason": "用户期限长+不确定底部"
  }
}
```

---

## 4. 选择决策矩阵

**触发**：用户问"选哪个"、"这两个有什么区别"

### 框架内容

> "两个标的的差异帮你整理一下："

| 考虑因素 | 选{标的A} | 选{标的B} |
|----------|-----------|-----------|
| 看重稳健 | ✓ | |
| 愿意承担更大波动 | | ✓ |
| 担心某成分拖累 | | ✓ |
| 相信龙头效应 | ✓ | |
| 看好弹性 | | ✓ |

> "{标的A}的特点：{一句话概括，如'龙头集中、波动大'}"
> "{标的B}的特点：{一句话概括，如'更分散、波动小'}"

### 引导问题

> "根据你自己的偏好，你更倾向选哪个？"

### 记录

```json
{
  "choice_decision": {
    "selected": "消费80",
    "reason": "用户看重分散+担心白酒拖累"
  }
}
```

## 收束话术

用户做完决策框架后：

> "好，我来帮你整理一下你的决策："
>
> "- 标的：{用户选择}"
> "- 仓位：{用户选择}"
> "- 方式：{用户选择}"
> "- 时机：{用户选择}"
>
> "确认一下，这是你想要的吗？"

用户确认后，生成执行计划文档。参见 [assets/exec_plan_template.md](../assets/exec_plan_template.md)。

## 多问题组合

用户可能一次问多个问题，如"我该买哪个、买多少、什么时候买"：

> "这几个问题我逐个帮你分析。"
>
> 先用**选择决策矩阵**确定标的 → 再用**仓位管理框架**确定仓位 → 再用**入场时机框架**确定时机

按需组合，逐个框架引导。
