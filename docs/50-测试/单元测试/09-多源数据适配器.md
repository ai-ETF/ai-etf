# 09-多源数据适配器

**被测模块**：`server/sources/`（14 个业务模块 + `__init__.py`）
**测试文件**：`tests/unit/server/sources/`（13 个文件，160 例）
**测试方法**：纯函数直测；状态机注入 `FakeClock` 驱动 `time.monotonic`；
HTTP 层用子类覆盖 `session` 注入 `FakeSession`；源类用子类覆盖
`_get_text` / `_get_json` 注入内联上游样本；akshare 调用用 `threading.Event`
构造超时、用 `monkeypatch` 替换超时包装。**全程禁网、禁外部 IO**。

## 功能

把净值、交易日历的取数从「单一源 + 静默吞异常」改为「按能力选源、逐源尝试、
域名级熔断」。本文档记录该适配器全部单元测试的数据集、预期与结果；设计契约见
[`../../20-设计/行情/数据源多源适配器.md`](../../20-设计/行情/数据源多源适配器.md)。

## 数据集建议

1. **`em_pingzhongdata` 补「累计净值缺日」样本**：分红/拆分时 `Data_ACWorthTrend`
   的点数与单位净值不一致。当前样本只验证了「日期能对上」，应补一组
   「累计数组少 2 天」的真实裁剪样本，断言缺失日期 `accumulated_nav is None`
   而不是错位取值。建议从 110020 真实响应裁剪后固化为 fixture，每季度回放。
2. **`em_fund_jjjz` 固化真实行数样本**：当前内联样本只验证结构（21 列、`showday`），
   行数量级靠 `MIN_ROWS=1000` 兜底。建议录制一份 2 万行量级的裁剪样本（保留
   110020、000001 与 2 行空净值），每周回放校验列数与行数，防止上游悄悄改列。
3. **`em_lsjz` 补服务端上限变化探测**：单测用替身验证了「每页 20 条」的分页逻辑，
   但无法发现上游把上限改成 30 或 0。现有契约测试只测 `pageSize=20`；建议在
   契约测试中补一条 `pageSize=100` 的断言（应仍返回 ≤20 条），一旦上游行为变化
   能立刻暴露。
4. **`em_mobile` 收集真实货基 `FTYPE` 文本**：当前按「包含『货币』」拒绝。
   若上游出现「理财型」「货币市场型」等新文案，`FTYPE` 字典需要补样本；
   建议固化 3–5 只真实货基的 `FTYPE` 值作为参数化样本。
5. **交易日历混淆串固化离线样本**：`klc_td_sh.txt` 只有 508 B，建议把**原文 +
   解码后的日期列表**一起存为 fixture，在 akshare 升级时离线回放；当前单测只验证
   DataFrame 之后的归一化，解码段仍只能靠契约测试。
6. **`events` 不需要真实数据**：字段与级别已按设计文档固定；若将来日志消费方
   依赖新字段，先改设计文档再补断言。
7. **`health` 不要用真实日志当单测数据**：阈值/冷却调优属于运行期观测（设计文档
   Q4），单测只锁定状态机语义，避免把经验参数固化成测试依赖。
