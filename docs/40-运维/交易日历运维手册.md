# 交易日历 · 运维手册

> 配套设计：[`交易日历缓存.md`](../20-设计/基金与交易/交易日历缓存.md)。
> 适用范围：A 股交易日历的**人工拉取**与**月度核验**。日历影响 T 日/确认日计算和净值调度，
> 不直接卡交易主链路，但错误会静默传播，因此核验不能省。
>生产在「推送迁移 + 部署代码 + 首次 `refresh`」完成前仍是旧内存缓存，
> 第 3 节起的命令不可执行；上线顺序见 §4.5。

## 2. 前置知识

| 项 | 值 |
|---|---|
| 交易日规则 | 周一至周五 − 法定节假日。**周末从不开市**，调休上班的周六日也不开市 |
| 源 | `sina_trade_date`：508 B，返回 1990-12-19 → 当年年末，约 8800 个交易日 |
| 覆盖区间 | 源返回的最早 → 最晚日期；整份落库，展开成自然日约 1.3 万行 |
| 权威依据 | 国务院办公厅《关于××年部分节假日安排的通知》；上交所/深交所休市安排公告 |
| 服务 | `fastapi.service`，部署目录 `/root/ai-etf`（见 [deploy skill](../../.claude/skills/deploy/SKILL.md)） |
| 管理接口 | `POST /api/admin/trading-calendar/refresh`、`GET /api/admin/trading-calendar/status` |
| 鉴权 | 请求头 `X-Admin-Token`，服务端与 `ADMIN_API_TOKEN` 比对；未配置时接口返回 503 |

### 2.1 暴露面

接口默认通过公网域名可达，靠 `ADMIN_API_TOKEN` 保护。若不需要公网触发，可在 Caddy 层限制来源 IP；
**接口鉴权不能省**。未配置 token 时接口返回 503，属于「默认关闭」。

## 3. 每月人工核验（只读）

### 3.1 状态接口

```bash
curl -sS -H "X-Admin-Token: $ADMIN_API_TOKEN" \
  https://ai-etf.xyz/api/admin/trading-calendar/status | python3 -m json.tool
```

返回应包含 `coverage_start`、`coverage_end`、`last_success_at`、`last_error`、
`days`、`trading_days`。接口只读，不触上游。

### 3.2 SQL 复核（接口不可用时）

在 Supabase SQL Editor 或 `psql` 执行：

```sql
-- 1) 状态：覆盖区间、最后成功、最近错误
SELECT coverage_start, coverage_end, last_success_at, last_error
FROM trading_calendar_state;

-- 2) 规模：总行数、交易日数、最早/最晚日期
SELECT count(*) AS days,
       count(*) FILTER (WHERE is_trading_day) AS trading_days,
       min(trade_date) AS first_day,
       max(trade_date) AS last_day
FROM trading_calendar;

-- 3) 下月非交易日：应只有周末 + 法定节假日
SELECT trade_date
FROM trading_calendar
WHERE trade_date >= date_trunc('month', current_date + interval '1 month')::date
  AND trade_date <  (date_trunc('month', current_date + interval '2 month'))::date
  AND NOT is_trading_day
ORDER BY trade_date;
```

### 3.3 判定标准

| 检查项 | 正常 | 异常处理 |
|---|---|---|
| `ready` | `true` | `false` → 快照未载入或读取失败，业务接口会报错；走 §4 拉取 |
| `coverage_end` | ≥ today + 45 天；11–12 月要求 ≥ 次年 1 月 1 日 | 走 §4 年度拉取；12 月仍不足则升级 |
| `coverage_start` | = 源最早日期（当前 1990-12-19） | 明显晚于源历史起点 → 快照被截断或写错，重跑 `dry_run` 核对 |
| `last_success_at` | 距上次年度拉取 ≤ 13 个月 | 超过 → 年度拉取漏做 |
| `last_error` | NULL，或已知且已处理 | 近期非空 → 查源日志；仍失败走 §6 |
| 下月非交易日 | 与国务院通知/交易所公告一致 | 不一致 → **暂停按日历下单/确认**，走 §4 并用公告核对 |
| 抽样 | 下月 1 日、月末、春节/国庆等已知节点抽查 1–2 个 | 不符 → 同上 |

### 3.4 核验记录

每次核验留一行（记在运维群或 issue，格式固定）：

| 日期 | 执行人 | coverage_end | last_success_at | 抽样结论 | 后续动作 |
|---|---|---|---|---|---|
| 2026-11-05 | sing | 2026-12-31 | 2026-10-18 | 11 月无额外休市 | 12 月安排年度拉取 |

## 4. 每年全量拉取（11–12 月）

### 4.1 前置条件（全部满足才执行）

1. 国务院办公厅已发布**下一年**节假日安排；
2. `dry_run` 返回的 `coverage_end ≥ 次年 1 月 1 日`；
3. 没有其他拉取在跑（并发调用会返回 409）。

> **不要因为「到了 12 月」就拉。** 源没更新时拉取只会得到旧区间，
> 跨年照样断档；此时应每周复检，而不是重复拉取。

### 4.2 步骤

```bash
# 1) 预览：只拉取 + 计算 diff，不写库、不替换内存
curl -sS -X POST \
  -H "X-Admin-Token: $ADMIN_API_TOKEN" \
  -H "Idempotency-Key: $(date +%s)-preview" \
  "https://ai-etf.xyz/api/admin/trading-calendar/refresh?dry_run=true" \
  | python3 -m json.tool
```

输出应包含：`coverage_start/end`、`source`、`stats{inserted,updated,unchanged,deleted}`、
`diff`、`elapsed_ms`。

```bash
# 2) 人工核验 diff 后正式写库并替换内存
curl -sS -X POST \
  -H "X-Admin-Token: $ADMIN_API_TOKEN" \
  -H "Idempotency-Key: $(date +%s)-apply" \
  https://ai-etf.xyz/api/admin/trading-calendar/refresh \
  | python3 -m json.tool
```

HTTP 状态：

| 状态码 | 含义 |
|---|---|
| 200 | 成功（含 `dry_run` 预览） |
| 401 | 管理凭证错误 |
| 409 | 已有拉取在跑 |
| 422 | 数据校验失败（为空、数量异常、覆盖区间非法），未写库 |
| 502 | 源失败（`SourceError` / `AllSourcesFailed`），未写库；`tried` 会说明原因 |
| 503 | 服务端未配置 `ADMIN_API_TOKEN`，接口默认关闭 |
| 504 | 拉取超时，未写库 |

### 4.3 diff 核验清单

重点看这些区间，其余可抽样：

| 区间 | 关注点 |
|---|---|
| 次年 1–2 月 | 元旦、春节（含调休） |
| 4 月 | 清明 |
| 5 月 | 劳动节 |
| 6 月 | 端午 |
| 9–10 月 | 中秋、国庆（两个假期可能相连） |

规则：

- 调休上班的周六/周日**必须仍是 `is_trading_day=false`**；
- 历史日期一般不应变化；出现变化说明源修正了历史数据，必须对照公告确认；
- 出现「改判」或「删除」必须对照公告确认后再正式调用；无法确认则中止（旧快照原样保留）。

### 4.4 执行后

1. 正式调用返回的 `stats` 与预览一致；不一致说明期间源或 DB 变了，重新核验；
2. 调 `GET /status` 复核覆盖区间与 `last_success_at`；
3. 抽查接口：下一交易日的确认日计算是否符合预期；
4. **不需要重启服务**：接口在服务进程内完成内存替换；
5. 记录到 §3.4 的表。

### 4.5 首次部署顺序（C1–C5 上线）

1. 推送迁移：`printf 'y\n' | supabase db push --linked`；
2. 在服务环境配置 `ADMIN_API_TOKEN`（不读 `.env`、不打印），重启服务；
3. 启动日志应出现「交易日历快照未载入（DB 为空或读取失败）」—— 首次部署属预期；
4. `POST refresh?dry_run=true` 核对覆盖区间与 diff，再正式调用；
5. `GET status` 确认 `ready=true`、`days/trading_days` 正常。

> 第 4 步完成前，依赖日历的接口（申购、赎回、15:37 确认任务）会返回 503 / 任务失败；
> 启动补偿 `confirm_pending_orders(skip_trading_day_check=True)` **不受影响** —— 这是刻意设计，
> 保证「先补偿存量订单、后刷新日历」的顺序可执行。

## 5. 临时调整（交易所公告）

触发场景：交易所临时延迟/暂停开市。先例：2020 年春节后开市由 1 月 31 日推迟到 2 月 3 日。

1. 确认公告来源（上交所/深交所官网）；
2. 先调 `refresh?dry_run=true` 看源是否已同步；
3. 源已同步 → 按 §4.2 正式调用；
4. 源未同步 → **以公告为准**，手工修正受影响日期（见 §7），并在核验记录里写明依据和操作人；
5. 通知相关方（下单/确认会受影响）。

## 6. 故障处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动日志 `calendar_ready=false` / 日历 ERROR | DB 为空或读取失败 | 调用 §4 拉取接口；新环境属于部署遗漏 |
| 业务接口报 `CalendarUnavailable` | 快照未载入 | 同上；进程能启动是刻意的，不会自动拉取 |
| 业务接口报 `CalendarOutOfCoverage` | 日期超出源覆盖区间（常见于跨年未拉取） | 走 §4 年度拉取；先 `dry_run` 确认 `coverage_end` |
| 502 且 `tried=[]` | 源处于熔断冷却期，**本次没有请求上游** | 等冷却结束再试（60s 起，最长 30 分钟）；急可重启服务清空熔断 |
| 502 且 `tried` 非空 | 上游网络层失败（超时/连接/403/429/5XX） | 看 `state.last_error`；稍后重试 |
| 502 且 `kind=PARSE_ERROR` / `SCHEMA_DRIFT` | 源格式变化或数据异常 | 不要靠重试解决；确认源是否改版，人工核对 |
| 401 | 凭证错误 | 重新准备 `ADMIN_API_TOKEN`（§2.1） |
| 409 | 已有拉取在跑 | 等前一个结束；不要并发重试 |
| 503 | 服务端未配置 `ADMIN_API_TOKEN` | 配置环境变量并重启服务（这是配置变更，不是日历刷新） |
| 504 | 拉取超时，未写库 | 保留旧数据；看 `state.last_error`；稍后重试 |
| `coverage_end` 不到次年 | 源尚未更新 | 每周复检；12 月仍无 → 人工确认交易所公告，必要时手工补 |
| 某天判断错误 | 源错误或手工误改 | 以公告为准修正单行（§7），记录来源；下次刷新前用 `dry_run` 核对冲突 |

## 7. 常见问题

- **为什么周末调休上班也不是交易日？**
  A 股交易所在周六日从不开市，调休安排不影响证券市场。
- **为什么现在存全量历史，而不是只存当年？**
  表语义是「最后一次成功快照」，整表替换最直接；约 1.3 万行、一次年度写入，成本可忽略。
  只存当年会引入「窗口外旧行」这类半快照状态。见设计 §4.2.1。
- **为什么不每天自动拉？**
  日历一年只在公布下一年安排时变化；日更只能提前发现，不能提高正确性，
  正确性靠人工核验。日更还会在源本身出错时每天复制同一份错数据。见设计 §4.5。
- **为什么不能用上证指数日 K 作为备源？**
  它只能覆盖已经发生过的交易日，给不出未来日期；换源会把 `coverage_end` 缩到今天，
  导致「下一交易日/跨年确认日」直接越界。见设计 §5。
- **为什么快照没载入时接口直接报错，而不是按工作日判断？**
  按星期几猜会把法定节假日当成交易日，确认日会算错；宁可让请求失败并暴露问题。
  见设计 §1.3、§4.6。
- **为什么拉取后不需要重启？**
  刷新接口在服务进程内执行，写完 DB 后直接原子替换内存快照。见设计 §4.3。
- **为什么接口要 `Idempotency-Key`？**
  写接口的幂等契约：整表替换本身幂等，key 用于日志追踪。值可以用时间戳。
