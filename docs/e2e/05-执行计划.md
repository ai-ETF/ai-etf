**关于 0.7 的重要澄清（降低协调成本）**：uni-app 会把 `.vue` 里**手写的 class 原样保留**到 `wxml`，所以 `page.$('.primary-btn')` 这类 **class 选择器是可用的**，不是非加 `id` 不可。真正会出问题的是三种情况：① 同类元素有多个（消息气泡、自选项、会话项）无法区分；② class 名是动态拼接的；③ 微信端**不支持父子选择器**、**不能跨组件查询**，导致定位不稳。

→ 因此把请求调整为：**为"列表中的可区分元素"补 `id`（属于必要），其余元素补 `id`（属于建议）**。前一类的清单是：`#chat-msg-list` 下的气泡、`#drawer-session-list` 下的会话项、`#wl-follow-item`、`#wl-tab-*`、`#buy-submit`/`#sell-submit`/`#login-submit`。

### 二.1 分支策略（实测后的结论）

**先澄清一个前提**：`ai-etf` 与 `application` 是两个**完全独立的 git 仓库**（无共同历史、无 submodule 关系）。所以"放同一个分支里"在物理上不可能——分支名是每个仓库各自的东西。能做的只是**两边用同一个分支名**，便于人对应。

**结论：`ai-etf` 一个分支就够，不要拆成"计划"和"代码"两个。**
