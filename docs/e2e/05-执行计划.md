## 一、总览：6 个阶段，3 条并行线

```
阶段 0 前置解阻 ──┬─► 阶段 1 L3 契约测试（后端线，你，独立）   ──┐
（阻塞全部）      │                                              │
                  ├─► 阶段 2 L1 前端单测（前端线，需抽 sse.ts）  ──┼─► 阶段 5 固化交接
                  │                                              │
                  └─► 阶段 3 L4 E2E 主体（共建，P4→P3→P1）      ──┤
                                    阶段 4 补 P2/P5 + L2         ──┘
```

| 阶段 | 内容 | 主要执行人 | 阻塞关系 | 预估 |
|---|---|---|---|---|
| **0** | 前置解阻（配置 + 环境 + 分支） | 前端同学 + 你 | **阻塞 1/2/3** | 0.5–1 天 |
| **1** | **L3 契约测试**（性价比最高） | **你**（不依赖任何人） | 仅依赖阶段 0 的 0.6 分支 | 1–2 天 |
| **2** | L1 前端单元测试 | 前端同学 | 需抽 `sse.ts` | 1–2 天 |
| **3** | **L4 E2E 主体**（P4 → P3 → P1，16 条） | 共建（前端跑、你出夹具） | 依赖阶段 0 全部 | 3–5 天 |
| **4** | P2 AI 对话 + P5 注册 + L2 集成 | 双方 | P2 需后端 mock 开关 | 2–3 天 |
| **5** | 固化 / 文档 / CI / 交接 | 你 | 依赖 1–4 | 0.5 天 |

**总计约 8–13 人天**，其中你的部分约 4–6 人天。

> **如果只有一周**：走 **0 → 1 → 3(P4 + P3 共 10 条)**，即"契约测试 + 两条最稳的 E2E 路径"。这个组合已经能覆盖 [02 §二](02-核心路径与分层策略.md) 里两个 P0（P4）+ 一个 P1（P3），且**完全不碰真实 LLM、不碰交易日、不写生产库**。

**关于 0.7 的重要澄清（降低协调成本）**：uni-app 会把 `.vue` 里**手写的 class 原样保留**到 `wxml`，所以 `page.$('.primary-btn')` 这类 **class 选择器是可用的**，不是非加 `id` 不可。真正会出问题的是三种情况：① 同类元素有多个（消息气泡、自选项、会话项）无法区分；② class 名是动态拼接的；③ 微信端**不支持父子选择器**、**不能跨组件查询**，导致定位不稳。

→ 因此把请求调整为：**为"列表中的可区分元素"补 `id`（属于必要），其余元素补 `id`（属于建议）**。前一类的清单是：`#chat-msg-list` 下的气泡、`#drawer-session-list` 下的会话项、`#wl-follow-item`、`#wl-tab-*`、`#buy-submit`/`#sell-submit`/`#login-submit`。

### 二.1 分支策略（实测后的结论）

**先澄清一个前提**：`ai-etf` 与 `application` 是两个**完全独立的 git 仓库**（无共同历史、无 submodule 关系）。所以"放同一个分支里"在物理上不可能——分支名是每个仓库各自的东西。能做的只是**两边用同一个分支名**，便于人对应。

**结论：`ai-etf` 一个分支就够，不要拆成"计划"和"代码"两个。**

| 仓库 | 分支 | 放什么 | 何时建 | 状态 |
|---|---|---|---|---|
| `ai-etf` | **`test/e2e`** | 全部：`docs/e2e/00–06` 文档 + `.claude/skills/e2e-testing/` + `tests/contract/` + `docs/e2e/scripts/e2e_fixture.py` + `pyproject.toml` 的 marker | **现在** | ✅ 已推送（基点 `origin/dev`）。契约测试 2026-09-24 完成并提交（`e8292fd` / `3fb07d5` / `2291d95`，**本地待推送**） |
| `application` | `chore/configurable-api-base` | 0.1 + 0.2（配置可外置）——**这是生产配置改动，不是测试代码** | 现在 | ✅ 已推送 `6fce4ff`，待 Windows 侧验证 |
| `application` | `test/e2e` | `jest.e2e.config.js` + `e2e/**` + package.json 的 devDeps/script + `.claude/skills/e2e-testing/` | **阶段 3 开始时** | ⬜ 未建（现在建是空分支，纯噪音） |

> ⚠️ **一个待办的不一致**：`e2e-testing` skill 在 `ai-etf` 那份**已经提交**了，但 `application` 那份**还没提交**。
> 两边现在**内容是一致的**（`sync_e2e_skill.sh --check` 通过），但 git 上只有一份。等 `application` 的 `test/e2e`
> 分支建起来时要一并提交，否则前端同学 clone 下来读不到规范。
>
> **2026-09-24 拍板：维持延后，不在现在补。** 理由有二：① 与上表「阶段 3 开始时」的排期一致，现在建只会得到一个仅含 skill 的分支；② `application` 当前停在 `chore/configurable-api-base`，那是 0.1 / 0.2 正在等 Windows 侧实测的分支，往里加提交会让组长验的 commit 与我手上的不一致。**风险已评估**：阶段 3 之前前端同学不需要读 skill（前置任务 `前端_端到端测试前置任务.md` 是独立文件，不依赖 skill），所以延后没有实际代价。

**为什么 `ai-etf` 合成一个分支**：我原先建议拆成 `test/e2e-plan`（文档）与 `test/e2e`（代码），理由是"文档要快点合、别被代码排期阻塞"。但实测后发现**契约测试同样不依赖任何人**——它读的是 FastAPI 的 `app.routes` 与 `openapi.json`，不碰前端、不联网。既然两者**同时 unblocked**，拆开就只剩坏处（多一次 rebase、review 时看不到全貌）。→ **合成 `test/e2e`，用 commit 分组**（`docs:` / `test:` 前缀），review 时按 commit 看。

**⭐ 命名有现成约定**：远程已有 `test/unit-pilot` 与 `test/integration-fixes` 两个分支 → **`test/e2e` 正好接上团队既有的命名习惯**，不需要发明新前缀。

**⚠️ 分支基点曾经有一个依赖（已解决）**：

```
origin/dev   = c93da83  "补上缺失的：重命名会话接口"      ← 当前（2026-09-21）
               └─ 3e08dff  "feat: 后端集成测试体系 + 修复 4 个缺陷 (#16)"
```

契约测试 C1 断言的是"前端 23 个调用点逐条存在"，其中一条是 `PUT /api/secure-chat/chats/{chat_id}/title`。
这条路由**一度只存在于 `fix/secure-chat-rename-title` 分支上**，当时若从 `dev` 拉分支会让 C1 必红。

> ✅ **已解决（2026-09-21）**：`dev` 已更新到 `c93da83`（"补上缺失的：重命名会话接口"），
> `PUT /chats/{chat_id}/title` **现在就在 `dev` 上**（`server/api/secure_chat.py:409`）。
> **所以直接从 `origin/dev` 拉 `test/e2e` 即可，不需要再从 fix 分支绕道。**
>
> ⚠️ 一个值得记住的教训：当时用 `git merge-base --is-ancestor fix/... origin/dev` 判定"未合并"，
> **结论是错的**。GitHub 上的 squash-merge / 重新提交会让分支的原始 commit **永远不成为 dev 的祖先**，
> 但内容其实已经进去了。**判"有没有合"要看内容（路由在不在），不能只看 commit 祖先关系。**

**`.gitignore` 的处理**：工作区那个未提交的 `M .gitignore`（忽略公众号文章）与 E2E **无关**。它是必需的（否则工作区不干净），但混进 `test/e2e` 会让 review 困惑 → 放进 `test/e2e` 分支但**单独一个 `chore:` commit**，并在 PR 描述里说明一句。

**具体操作**（✅ 已于 2026-09-21 执行完毕）：

```bash
cd ai-etf
git fetch origin
git checkout -b test/e2e origin/dev   # 基点用 dev（2026-09-21 起 dev 上已有 PUT .../title 路由）
# docs/e2e/ 是未跟踪文件，会自动跟过来
git add .gitignore && git commit -m "chore: 追加两条忽略规则"             # 单独一个 chore commit
git add docs/e2e/ && git commit -m "docs: E2E 测试规划（00–06）+ skill 同步脚本"
git add .claude/skills/e2e-testing/ && git commit -m "docs: 新增 e2e-testing skill"
git update-index --chmod=+x docs/e2e/scripts/sync_e2e_skill.sh   # Windows 磁盘记不住可执行位
git push -u origin test/e2e
```
