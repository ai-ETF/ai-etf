## 2. 为什么花了这么久（三条主线）

不是「试错次数多」，是三个坑都**不报错或报假错**，每个都必须读到源码才能定位：

| # | 现象 | 真实原因 | 为什么难查 |
|---|------|---------|-----------|
| A | `spawn EINVAL` | WSL 的 `cmd.exe` 会吃掉路径参数的双引号，而小程序项目路径含中文（`D:\C1\Have a try\...`）+ 中文工具路径 | 报错信息完全没提路径/引号 |
| B | 用例永久挂起，日志里**只有** `gettestpublib`，没有任何错误 | 上一轮开发者工具还占着 `--auto-port`，这一轮的 `auto` 撞上自己 → `throw Error('Port is in use')` → **静默不 openProject** | 开发者工具**不报这个错**，日志也不写，只有读它自己的 `exports.auto` 源码才知道有这道校验 |
| C | 项目窗口卡死，小程序根本不运行 | 开发者工具的 per-project `dirCache` 过时（uni 重新构建 dist 后对不上） | 窗口日志停在 `[hybirdLog] real init !` 就没了，**无 ERROR、无异常**，纯静默 |

## 3. 跑通的完整前置条件（缺一不可）

### 3.1 `application/jest.e2e.config.js`

| 项 | 值 | 为什么 |
|----|-----|--------|
| `executablePath` | `D:/Program Files (x86)/Tencent/微信web开发者工具/cli.bat` | uni-automator 硬编码找 C 盘，本机装在 D 盘，不写会报 `Wechat web devTools not found` |
| 顶层 `port` | `9520` | **uni-automator 自己的端口**：既用于注入到小程序的 `wsEndpoint`，也用于它自己 `new ws.Server`。默认值就是 9520，**别去改它** |
| `mp-weixin.port` | `9420` | 只传给开发者工具的 `--auto-port`，开发者工具自己在上面监听。默认值就是 9420 |
| `host` | `127.0.0.1` | 不设时 uni 取本机**内网 IP**（实测注入成 `ws://10.161.145.211:9520`），换个网络/换台机器就挂 |
| `timeout` | `60000` | 不设时 `createRuntimeConnection` 用常量 240000，失败一次干等 4 分钟 |
| `teardown` | `'quit'` | **必须**。见 3.2 |
| `compile` | `true` | 触发 uni 构建并注入自动化 SDK |

> **两个端口的关系是这套东西最容易踩的地方**，两条依据：
> - `uni-automator/dist/index.js:35356` —— `timeout: t.timeout || zt`、`port: t.port || 9520`
> - `uni-mp-weixin/lib/uni.automator.js` —— `e.port || t.devtools.defaultPort`，`defaultPort: 9420`
>
> 两者**必须不同**。若顶层被设成 9420，开发者工具会撞上 uni 自己的监听 → 静默拒绝打开项目。

### 3.2 `teardown` 为什么必须是 `quit`（实测）

**不能图快用 `disconnect`。** 开发者工具会把 `--auto-port`（9420）一直 `LISTENING` 着，
进程不退、端口不放。下一轮 jest 再发 `auto --auto-port 9420` 会撞上它自己的监听：

```js
// 开发者工具自身源码（WeappCache/requireCache/.../require-file.json）
exports.auto = async o => {
  let { port: l } = o
  if (await getPort(l) !== l) throw Error(`Port ${l} is in use`)   // ★ 静默卡在这
  await f(i, { autoPort: l, ... })                                 // ← 过了这关才会 openProject
}
```

实测：`disconnect` 下**第二次连续 jest 必挂**，报 `Failed to connect to runtime`；
`quit` 下两轮连续 PASS。代价是每轮多约 10s 冷启动。

### 3.3 开发者工具 `dirCache` 会过时（坑 C，最隐蔽）

**症状**：项目窗口日志停在

```
[hybirdLog] real init !          ← 到此为止，后面什么都没有
```

正常应该接着 `[cloudapi/getSharedEnvInfo] []` → `init !!!!!` → `compile onFileChange ...`。

**原因**：开发者工具把项目目录的文件清单缓存在
`<User Data>/WeappCache/dirCache/<项目路径hash>/fileCache.cfg`。
uni 每次构建都会重写 `dist/dev/mp-weixin`，缓存与实际文件对不上时，
窗口初始化后**不再继续**，小程序既不编译也不运行 → 自动化 SDK 自然不会回连。

**处置**：删掉该目录即可恢复（已实测）：

```bash
# User Data 路径（本机）
U="/mnt/c/Users/13553/AppData/Local/微信开发者工具/User Data/3e5d725bf5abbd2bfd7bc047ee989e46"
rm -rf "$U/WeappCache/dirCache/"*
```

**注意**：清 `dirCache` 是可复现的**应急手段**，不是常规步骤。
先走 §4 的标准流程；只有窗口卡在 `real init !` 时才清。

### 3.4 编译产物里的 `urlCheck`（⚠️ 后来发现它**不是**硬前置）

dist 里的 `project.config.json` 每次构建都被重新生成，直接改它没用，要改**源头**。
源头的正确落点是 **`application/src/project.private.config.json`**（见 §6.2），
它会被拷进 `dist/dev/mp-weixin/`，开发者工具读配置时 **private 覆盖 public**。

> **2026-10-02 修正**：本节原先写「必须改 `src/manifest.json`」，**这是错的**。
> 当时把 private config 放在了**仓库根目录**，而 uni 只从 **`src/`** 拷贝它，
> 所以「改了不生效」被误判成「这条路不通」。放进 `src/` 后实测生效，
> 而且不用碰任何源码。
>
> **2026-10-03 再修正（更根本）**：`urlCheck: false` **到底是不是必需的，其实没被证明**。
> 实测把它设回 `true`（此时生效 appid 是真号 `wx4345af65c586dd70`），**整套 P4 依然全绿**，
> 包括需要一次真实 HTTP 往返才能拿到 401 的 P4-02 —— 说明请求确实发出去了。
> 也就是说开发者工具在当前配置下**可能本来就放行 localhost**。
> 保留 `urlCheck: false` 是零成本保险（将来换真 appid 时更可能需要），
> **但「必须关 urlCheck」不是已验证的事实。** 表述见 [07 §6](07-小程序E2E环境配置说明.md)。

### 3.5 开发者工具必须在 GUI 里登录过

CLI 拿不到 AppID 权限时 `auto` 会直接失败。服务端口要打开，且**要在 GUI 里扫码登录**。

### 3.6 WSL 侧：路径加引号补丁（坑 A）

WSL 调 `cmd.exe` 会吃掉参数里的双引号，而本机路径含中文。
需要在 spawn 处给 CLI 路径和项目路径加引号 —— 详见 §5 的补丁清单。

## 4. 标准执行流程（今天实测有效的）

0. ⚠️⚠️ **先确认构建产物打的是本地后端，不是生产** —— 这是唯一的**数据安全**前置：

   ```bash
   grep -o 'const API_BASE = "[^"]*"' \
     "/mnt/d/C1/Have a try/etf/code/application/dist/dev/mp-weixin/config/index.js"
   # 必须输出：const API_BASE = "http://localhost:8000"
   # 若输出 https://ai-etf.xyz —— 停！那是【生产】，E2E 会真写生产库
   ```

   **为什么会出事**：[config/index.ts](application/src/config/index.ts) 的兜底值是
   `'https://ai-etf.xyz'`（生产）。它的设计意图是"忘配环境变量时行为与改动前一致"，
   但对 E2E 而言这意味着：**`.env.development` 一旦缺失或没配 `VITE_API_BASE`，
   请求就会打到生产。** 换机器、重装依赖、改了构建模式都可能触发。
   配套：后端库必须是本地 Supabase 栈（见 [05 §二 0.8](05-执行计划.md)）。

1. 确认开发者工具已登录、服务端口已打开。
2. **确认 9420 没有被 `Listen` 占着**（这是最容易踩的一步，见 §6.3）：
   ```powershell
   Get-NetTCPConnection -LocalPort 9420,9520   # 期望：没有 Listen
   ```
   有 `Listen` 就 `taskkill /F /IM wechatdevtools.exe` 一次杀光再跑。
3. 跑（**2026-10-03 起用这条**，`npm run test:e2e` 会自动先应用 node_modules 补丁）：
   ```bash
   # Windows 侧，仓库根目录
   npm run test:e2e
   ```
   旧的 `D:\run_e2e.cmd` 仍可用（它直接调 jest、不打补丁），但**新环境请用上面这条**。
   只跑 P4：`npm run test:e2e -- -t 'P4'`。
4. 看成功的标志：**`automator:runtime ... connected`** 这一行。
   只有 `automator:devtool connected` 是不够的（那只说明连上了开发者工具）。
5. 失败时的判据：
   - 只剩 `automator:devtool connected` + `Failed to connect to runtime` → 
     去看项目窗口日志是不是卡在 `real init !`（→ 清 `dirCache`，§3.3）
   - 日志里连 `openProjectSimulatorDebuggerAndCompile start` 都没有 → 
     端口自撞（§3.2）

**日志位置**（本机）：
`C:\Users\13553\AppData\Local\微信开发者工具\User Data\3e5d725bf5abbd2bfd7bc047ee989e46\WeappLog\logs\`
每次运行产生**两条**：主进程日志（约 10KB，含 `cli ws recv` / `openProject`）
+ 项目窗口日志（工作正常时约 50KB，含 `compile onFileChange`）。

### 5.2 `node_modules` 补丁（**已于 2026-10-03 固化成脚本**）

**补丁面已精确核实**（2026-10-03）：拿一份**干净重装**的 `node_modules` 与工作区逐文件比对，
24692 个文件里**只有 2 个文件**内容不同（外加 npm 自己的 `.package-lock.json` 记账差异）：

| 文件 | 补丁 | 作用 |
|------|------|------|
| `@dcloudio/uni-mp-weixin/lib/uni.automator.js` | spawn 选项加 `shell: true` | 解 `spawn EINVAL`（坑 A）—— **根因** |
| 同上 | CLI 路径、项目路径各加一层引号 | `shell: true` 之后命令要过 cmd.exe，路径含空格会被切开 |
| 同上 | `stdio: "ignore"` → `"inherit"` | **纯诊断用**，能看到 CLI 输出 |
| `@dcloudio/uni-automator/dist/index.js` | spawn 选项加 `shell: true` | 同一类修复的另一条 spawn 路径 |

**根因说清楚**：不是「中文路径」本身。Node 从 18.20.2 / 20.12.2 / 22 起为堵
BatBadBut（CVE-2024-27980）改了行为，**不带 `shell: true` spawn `.bat` / `.cmd` 会直接抛 EINVAL**。
本机 Node 是 v22.21.0，正好在这条线上。补上 `shell: true` 之后又引出路径要加引号 —— 所以这 4 处是一套，不能只挑一半。

**固化方式**（2026-10-03 已落地）：
`application/e2e/patches/apply-node-modules-patches.js` —— 把上面 4 处写成**精确整串替换**，幂等，找不到就报错退出。
由 `npm run test:e2e` 在开跑前自动应用（也可单独 `npm run e2e:patch`）。
**故意不做 `postinstall` 钩子**：这两个文件只有跑 E2E 才走到，日常 `dev:mp-weixin` / `build` 完全不碰，
不该让不跑 E2E 的人承担副作用。

> 为什么不用 `patch-package`：这两个文件是压缩过的超长单行 JS（`uni.automator.js` 只有 2 行），
> 按行做 diff/patch 没有意义；精确整串替换更稳、也更好审。
> 备份仍在 `/mnt/d/uni.automator.js.bak-shelltrue`、`/mnt/d/uni-mp-weixin.automator.js.orig`。

**验证方式**：把 2 个文件还原成干净版，跑脚本，再与被还原前的可用状态 `cmp` → **逐字节一致**；重跑 → 跳过。

**另一条路（未采用）**：用 nvm-windows 装 Node 18.20.1（BatBadBut 修复之前）可彻底免掉补丁 ——
但那要降 Node 版本、还退回了漏洞修复，不划算。

### 6.2 真实 AppID 的权限问题（**2026-10-02 已找到不碰源码的绕法**）

- 小程序 AppID `wx4345af65c586dd70` 要求开发者权限，**当前微信账号没有** →
  开发者工具报 `登录用户不是该小程序的开发者`（code 10）→ CLI 退出 →
  uni-automator 报 **`Failed to launch Wechat web DevTools, please make sure http port is open`**。
  ⚠️ **最后那句报错是误导的，跟端口无关**，是权限问题。别往端口方向查。
  （想一眼看到真话，用 CLI 手跑一次：`cli.bat auto --project <产物目录> --auto-port 9420`。）
- 副作用：开发者工具报 `gettestpublib Error 41002, appid missing`。
  **已证实这个错不影响跑通**（成功和失败的运行里都有它），但它意味着
  游客模式下拿不到测试库/发布相关能力。

**绕法（2026-10-02 起，取代原来的「改 manifest.json」）**：

新增 `application/src/project.private.config.json`，内容：

```json
{ "appid": "touristappid", "setting": { "urlCheck": false } }
```

`src/manifest.json` **一行都不用改，保持原样**。

**为什么必须是 `src/` 而不是仓库根目录**：uni 的拷贝清单
（`@dcloudio/uni-mp-weixin/dist/uni.compiler.js:211-232` 的 `copyOptions.targets`）
里的路径是相对**编译入口目录**（`src/`）解析的。放根目录不生效 ——
**这不是推断，是实测**：放根目录 → dist 里没有这个文件；放 `src/` → 出现且生效。

开发者工具读配置的规则是 **private 覆盖 public**，所以 private 里的 `appid`/`urlCheck`
会盖掉 uni 生成的那份 `project.config.json`（那份永远是真 appid + `urlCheck: true`）。

⚠️ **不要依赖 `/tmp` 做备份** —— WSL 重启会清空 `/tmp`，
本次实测的 `/tmp/manifest.json.bak` 就已经消失。要备份请放在仓库外的固定目录，
或直接依赖 git。

> ✅ **2026-10-03 解决**：开发者权限**已经加好了**，实测真 appid 能正常打开项目跑测试。
> 但 private config 里**仍然保留 `touristappid`** —— 理由与切换方式见 [07 §3.2](07-小程序E2E环境配置说明.md)。

#### 6.2.1 appid 的三条出路

| 方案 | 怎么做 | 代价 |
|---|---|---|
| **A. 游客模式**（现在用的） | private config 里写 `touristappid` | 随时能用、零成本。但**拿不到测试库/发布能力**（41002），且不是真实 appid —— 测不了任何与 appid 绑定的东西（`wx.login` 的真实 code、云能力） |
| **B. 加开发者权限**（根治） | 管理员在微信公众平台后台把小组成员加进「开发者」列表 | 一次性的、需要管理员扫码。加完就能用真 appid 跑，最接近真实环境。✅ **2026-10-03 已完成并实测通过** |
| **C. 申请小程序测试号** | 微信提供「小程序测试号」，个人也能申请，不需要企业主体 | 不用求人，但测试号的功能和真号有差异（部分接口不支持），属于 B 走不通时的替代 |

**当前选择（2026-10-03 定）**：**A 和 B 都已经可用，但提交进仓库的是 A**。
理由：B 的权限是**跟着账号走**的，而 private config 要提交给所有人用 ——
写 `touristappid` 谁 clone 下来都能跑，写真号则只有有权限的账号能跑（撞上 §6.2 那句误导报错）。
**要切真号就改一行**，条件与理由见 [07 §3.2](07-小程序E2E环境配置说明.md)。
