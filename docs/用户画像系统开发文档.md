# 用户画像系统开发文档

> 版本：v1.0
> 更新日期：2026-07-28
> 对应阶段：Step 1~4（问卷获取 → 画像标签）

---

## 一、概述

实现用户画像获取的完整后端链路：用户获取问卷 → 填写提交 → 系统根据答案计算画像标签 → 存储并返回画像结果。

### 链路流程

```
前端                    后端                          Supabase
  │                      │                              │
  ├─ GET /questionnaire ─→ 读取最新可用问卷 ───────────→ risk_questionnaires
  │←── 问卷题目 ─────────┤                              │
  │                      │                              │
  ├─ POST /submit ───────→                              │
  │    {answers}          ├─ 验证答案有效性               │
  │                      ├─ 计算风险评分                  │
  │                      ├─ 存入答题记录 ───────────────→ user_risk_answers
  │                      ├─ 生成画像标签 ───────────────→ user_risk_profiles
  │←── 画像结果 ──────────┤                              │
  │                      │                              │
  ├─ GET /profile ──────── 读取最新画像 ────────────────→ user_risk_profiles
  │←── 画像详情 ──────────┤                              │
```

## 二、数据库表结构

三张表已存在于 Supabase 中，结构如下：

### 2.1 risk_questionnaires

全局问卷配置表，所有认证用户可读。

| 字段 | 类型 | 说明 |

| id | uuid PK | 主键 |
| version | text | 问卷版本号（如 v1.0） |
| questions | jsonb | 问卷题目数组 |
| is_active | bool | 是否启用 |
| created_at | timestamptz | 创建时间 |
| updated_at | timestamptz | 更新时间 |

**questions 结构示例：**

```json
[
  {
    "id": "q1",
    "question": "你通常计划持有一只 ETF 多长时间？",
    "description": "投资期限维度，反映时间维度风险",
    "category": "investment_horizon",
    "weight": 0.2,
    "options": [
      {
        "text": "少于 1 年，偏向短期配置",
        "value": "A",

        "risk_score": 1,
        "explanation": "短期配置，风险承受能力较低"
      },
      { "text": "1–3 年，视情况调整", "value": "B",
        "risk_label": "moderate", "risk_score": 2, ... },
      { "text": "3 年以上，长期持有", "value": "C",
        "risk_label": "aggressive", "risk_score": 3, ... }
    ]
  }

```

### 2.2 user_risk_answers

用户答题记录表，按 user_id 隔离。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | 主键 |
| user_id | uuid | 用户 ID（来自 JWT） |
| questionnaire_id | uuid | 关联的问卷 ID |
| answers | jsonb | 用户答案数组 |
| is_completed | bool | 是否完成 |
| session_id | text | 会话标识 |
| created_at | timestamptz | 创建时间 |

**answers 结构：**

```json
{
  "q1": "B",
  "q2": "A",
  "q3": "C",
  "q4": "B",
  "q5": "B"
}
```

注意：`answers` 以 `{question_id: value}` 键值对对象格式存储，这是 `chk_answers_object` 约束要求的格式，而不是数组格式。

### 2.3 user_risk_profiles

用户画像表，按 user_id 隔离。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | 主键 |
| user_id | uuid | 用户 ID |
| answer_id | uuid | 关联的答题记录 ID |
| risk_level | text | 风险等级：conservative / moderate / aggressive |
| risk_label | text | 中文标签：保守型 / 稳健型 / 进取型 |
| total_score | numeric | 加权总分 |
| weighted_scores | jsonb | 各题加权得分明细 |
| dimension_scores | jsonb | 各维度得分 |
| confidence_score | numeric | 置信度（当前固定 1.0） |
| ai_summary | text | 画像解读摘要 |
| profile_source | text | 来源：rule-based / ai |
| model_version | text | 规则版本 |
| is_active | bool | 是否有效（默认 true） |
| metadata | jsonb | 扩展信息 |
| expires_at | timestamptz | 过期时间 |
| created_at | timestamptz | 创建时间 |

## 三、画像计算规则（Rule-based）

### 3.1 加权总分

```
total_score = Σ(risk_score_i × weight_i) / Σ(weight_i)
```

- `risk_score_i`：用户在第 i 题所选选项的风险得分（1 / 2 / 3）
- `weight_i`：第 i 题的权重（`q1=0.2, q2=0.3, q3=0.15, q4=0.25, q5=0.1`，总和 = 1.0）
- 分母 Σ(weight_i) 恒为 1.0，所以实际上 total_score = Σ(risk_score_i × weight_i)

### 3.2 等级判定

| 总分范围 | risk_level | risk_label | 说明 |
|---|---|---|---|
| total_score ≤ 1.6 | conservative | 保守型 | 低风险偏好，注重本金安全 |
| 1.6 < total_score ≤ 2.4 | moderate | 稳健型 | 中等风险偏好，风险收益平衡 |
| total_score > 2.4 | aggressive | 进取型 | 高风险偏好，追求长期收益 |

### 3.3 维度得分

每道题的 `category` 即为一个维度。维度得分为该题选中的 `risk_score`（不做加权平均，直接透传每道题原始得分）。

```json
{
  "investment_horizon": 2,
  "drawdown_tolerance": 2,
  "investment_experience": 3,
  "goal_orientation": 2,
  "knowledge_level": 2
}
```

### 3.4 AI 摘要生成（可选增强）

计算画像后，可用 LLM 生成一段中文画像解读摘要，填充到 `ai_summary` 字段。在 v1 阶段建议先用**模板摘要**，后续再接入 LLM。

模板规则：
- conservative → "您属于保守型投资者，倾向于低风险、稳定回报的投资方式，注重本金安全和流动性。"
- moderate → "您属于稳健型投资者，在控制风险的前提下追求适度收益，风险与收益并重。"
- aggressive → "您属于进取型投资者，愿意承担较高风险以换取更高的长期投资回报。"

## 四、API 接口设计

### 4.1 获取问卷

获取当前最新可用的风险问卷，返回结构化的题目列表供前端渲染。

```
GET /api/risk/questionnaire
Authorization: Bearer <jwt_token>
```

**Response 200：**

```json
{
  "id": "34d97ea8-ccfa-4f4b-adc7-92234362b06f",
  "version": "v1.0",
  "questions": [
    {
      "id": "q1",
      "question": "你通常计划持有一只 ETF 多长时间？",
      "category": "investment_horizon",
      "options": [
        { "text": "少于 1 年，偏向短期配置", "value": "A" },
        { "text": "1–3 年，视情况调整", "value": "B" },
        { "text": "3 年以上，长期持有", "value": "C" }
      ]
    }
    // ... 共 5 题
  ],
  "total_questions": 5
}
```

> 注意：返回给前端的题目中**不包含** risk_score、weight 等内部计算字段，仅保留 question、options(text+value)、category。

### 4.2 提交问卷答案

```
POST /api/risk/submit
Authorization: Bearer <jwt_token>
Content-Type: application/json

{
  "questionnaire_id": "34d97ea8-ccfa-4f4b-adc7-92234362b06f",
  "answers": [
    { "question_id": "q1", "value": "B" },
    { "question_id": "q2", "value": "A" },
    { "question_id": "q3", "value": "C" },
    { "question_id": "q4", "value": "B" },
    { "question_id": "q5", "value": "B" }
  ]
}
```

**后端处理流程：**

1. 校验 questionnaire_id 是否存在
2. 校验 answers 覆盖全部题目（5 题缺一不可）
3. 校验每个 question_id + value 组合在问卷选项中存在
4. 从问卷中匹配每个答案的 risk_score、weight
5. 计算 total_score，判定 risk_level
6. 存入 `user_risk_answers` 表
7. 存入 `user_risk_profiles` 表
8. 返回画像结果

**Response 201：**

```json
{
  "success": true,
  "message": "问卷提交成功",
  "profile": {
    "risk_level": "moderate",
    "risk_label": "稳健型",
    "total_score": 2.1,
    "dimension_scores": {
      "investment_horizon": 2,
      "drawdown_tolerance": 1,
      "investment_experience": 3,
      "goal_orientation": 2,
      "knowledge_level": 2
    },
    "summary": "您属于稳健型投资者，在控制风险的前提下追求适度收益，风险与收益并重。"
  }
}
```

### 4.3 查询用户画像

```
GET /api/risk/profile
Authorization: Bearer <jwt_token>
```

返回当前用户的最新画像（`is_active=true` 且按 `created_at` 降序取第一条）。

**Response 200：**

```json
{
  "has_profile": true,
  "profile": {
    "risk_level": "moderate",
    "risk_label": "稳健型",
    "total_score": 2.1,
    "dimension_scores": {
      "investment_horizon": 2,
      "drawdown_tolerance": 1,
      "investment_experience": 3,
      "goal_orientation": 2,
      "knowledge_level": 2
    },
    "summary": "您属于稳健型投资者，在控制风险的前提下追求适度收益，风险与收益并重。",
    "created_at": "2026-07-28T12:00:00+00:00"
  }
}
```

**未填写时返回：**

```json
{
  "has_profile": false,
  "profile": null
}
```

### 4.4 健康检查

```
GET /api/risk/health
```

无需认证，用于验证模块是否正常加载。

**Response 200：**

```json
{
  "status": "ok",
  "service": "risk"
}
```

## 七、错误处理

| 场景 | HTTP Status | message |
|---|---|---|
| 问卷不存在 | 404 | 问卷不存在或已停用 |
| 答案未覆盖全部题目 | 400 | 请回答全部题目 |
| 答案包含无效选项 | 400 | 问题 {qid} 的选项 {value} 无效 |
| 用户已提交过（同一问卷） | 200（覆盖旧记录） | 已提交过该问卷，将覆盖旧记录 |
| JWT 无效/过期 | 401 | 令牌无效或已过期 |

> 关于重复提交：如果同一个用户对同一份 `questionnaire_id` 重复提交，当前设计**覆盖旧记录**（更新 user_risk_answers + user_risk_profiles），不会拒绝。返回状态码 200 而不是 409。
