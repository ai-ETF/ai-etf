# 01 基础 & 认证

健康检查与登录接口。**登录是全局唯一的认证入口**，其余模块的 `$TOKEN` 均从这里获取。

## 环境变量

```bash
API="https://ai-etf.xyz"           # 远程（HTTPS）；本地改为 http://localhost:8000
EMAIL="<你的邮箱>"
PASSWORD="<你的密码>"
```

## 接口速查

| 方法 | 路径 | 认证 |
|------|------|:---:|
| GET | `/` | - |
| GET | `/api/test/hello` | - |
| POST | `/api/secure-chat/register` | - |
| POST | `/api/secure-chat/login` | - |
| POST | `/api/secure-chat/refresh` | - |
| POST | `/api/secure-chat/logout` | JWT |
| POST | `/api/secure-chat/delete-account` | JWT |

## 1. 服务健康检查

**方法 / 路径：** `GET /`（公开）

```bash
curl -s "$API/" | python3 -m json.tool
```

## 2. 测试端点

**方法 / 路径：** `GET /api/test/hello`（公开）

```bash
curl -s "$API/api/test/hello" | python3 -m json.tool
```

## 3. 登录获取 JWT

**方法 / 路径：** `POST /api/secure-chat/login`（公开，全站唯一登录入口）

**说明：** 校验邮箱密码（Supabase Auth），返回 `access_token`（1 小时）与 `refresh_token`（长效，Supabase 默认 30 天，用于免登录）。所有需认证接口在 Header 携带 `Authorization: Bearer <token>`。

**curl 示例：**

```bash
# 方式一：直接看完整响应
curl -X POST "$API/api/secure-chat/login" \
  -H "Content-Type: application/json" \
  -d "{\"email\":\"$EMAIL\",\"password\":\"$PASSWORD\"}" | python3 -m json.tool

# 方式二：只提取 token 写入变量（后续文档统一用 $TOKEN / $AUTH）
TOKEN=$(curl -s -X POST "$API/api/secure-chat/login" \
  -H "Content-Type: application/json" \
  -d "{\"email\":\"$EMAIL\",\"password\":\"$PASSWORD\"}" \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")
AUTH="Authorization: Bearer $TOKEN"
echo "Token: ${TOKEN:0:20}..."

# 方式三：一次性提取 access + refresh（推荐，免登录场景用）
LOGIN=$(curl -s -X POST "$API/api/secure-chat/login" \
  -H "Content-Type: application/json" \
  -d "{\"email\":\"$EMAIL\",\"password\":\"$PASSWORD\"}")
TOKEN=$(echo "$LOGIN" | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")
REFRESH=$(echo "$LOGIN" | python3 -c "import sys,json; print(json.load(sys.stdin)['refresh_token'])")
AUTH="Authorization: Bearer $TOKEN"
```

**请求体：**

| 字段 | 类型 | 必需 | 说明 |
|------|------|:---:|------|
| email | string | ✅ | 邮箱 |
| password | string | ✅ | 密码 |

**响应示例：**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "v1.MRqX...",
  "token_type": "bearer",
  "user_id": "uuid-string",
  "expires_in": 3600
}
```

> token 有效期 3600 秒（1 小时）。登录失败返回 401「邮箱或密码错误」。
>
> `refresh_token` 是长效凭证，**等同密码**：前端需持久化保存（小程序 `uni.setStorageSync`），access_token 过期后用它调 [§4 刷新登录态](#4-刷新登录态免登录核心)换新 token，避免让用户重新登录。

## 4. 刷新登录态（免登录核心）

**方法 / 路径：** `POST /api/secure-chat/refresh`（**公开，无需 JWT**）

**说明：** 用 `refresh_token` 换取新的 `access_token`。调用它时 access_token 通常已过期，故不要求 JWT —— 凭证就是请求体里的 `refresh_token` 本身。

**前端必须知道的一件事：** Supabase 开启了 refresh token 轮转，**每次刷新都会返回一个新的 `refresh_token` 并作废旧的**。前端必须用返回值**覆盖**本地保存的 refresh_token，否则下次刷新会因「旧 token 已作废」而 401。

**请求体：**

| 字段 | 类型 | 必需 | 说明 |
|------|------|:---:|------|
| refresh_token | string | ✅ | 登录 / 注册 / 上次刷新返回的 refresh_token |

**curl 示例：**

```bash
# 刷新一次并打印结果
curl -X POST "$API/api/secure-chat/refresh" \
  -H "Content-Type: application/json" \
  -d "{\"refresh_token\":\"$REFRESH\"}" | python3 -m json.tool

# 刷新并更新变量（注意：返回的 refresh_token 与传入的不同，必须覆盖）
NEW=$(curl -s -X POST "$API/api/secure-chat/refresh" \
  -H "Content-Type: application/json" -d "{\"refresh_token\":\"$REFRESH\"}")
TOKEN=$(echo "$NEW" | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")
REFRESH=$(echo "$NEW" | python3 -c "import sys,json; print(json.load(sys.stdin)['refresh_token'])")
AUTH="Authorization: Bearer $TOKEN"
```

**响应示例（`200`）：**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "v1.NEWTOKEN...",
  "token_type": "bearer",
  "user_id": "uuid-string",
  "expires_in": 3600
}
```

**错误：**

| 状态码 | 含义 | 前端处置 |
|:---:|---|---|
| `400` | 请求体缺少 refresh_token | 客户端 bug |
| `401` | refresh_token 无效 / 已过期 / 已被轮转作废 / 已登出 | **清空本地凭证并跳登录页** |
| `422` | 字段缺失（Pydantic 参数校验） | 客户端 bug |
| `429` | 请求过于频繁（Supabase 限流） | 稍后重试 |
| `500` | 数据库连接未就绪 | 服务端问题 |
| `502` | 刷新服务暂时不可用 | 稍后重试；**不要**当作登录失效 |

> ⚠️ **并发陷阱**：轮转下一个 refresh_token 只能成功使用一次。小程序冷启动常并发数个请求，若同时 401 并各自发起刷新，只有一个成功、其余拿到 401 —— 用户被无故踢下线。前端必须用**全局单例锁**：同一时刻只允许一个刷新在途，其余调用方等待同一个结果。
>
> ⚠️ **`502` 与 `401` 必须区分**：`401` 才代表登录态真的失效（清本地凭证）；`502` 是服务端/网络抖动，此时清凭证会让用户在服务恢复正常后仍被登出。

## 5. 注册账号

**方法 / 路径：** `POST /api/secure-chat/register`（公开）

**说明：** 调用 Supabase Auth 注册新用户。设计模式为 auto-confirm，注册成功即激活并直接返回 `access_token`，前端可用其作为登录态。密码至少 8 位。

> ⚠️ 该模式要求 Supabase 项目端**关闭 `Confirm email` 开关**（Authentication → Sign In / Providers → Email）。Supabase 该项**默认是开启的**；若未关闭，注册会因邮件发送限流失败，返回 `429`。详见 [用户注册 §11](../20-设计/账户与认证/用户注册.md)。

**请求体：**

| 字段 | 类型 | 必需 | 说明 |
|------|------|:---:|------|
| email | string | ✅ | 邮箱，格式校验 |
| password | string | ✅ | 密码，至少 8 位 |

**curl 示例：**

```bash
curl -X POST "$API/api/secure-chat/register" \
  -H "Content-Type: application/json" \
  -d "{\"email\":\"$EMAIL\",\"password\":\"$PASSWORD\"}" | python3 -m json.tool
```

**响应示例（auto-confirm 模式，`201`）：**

```json
{
  "success": true,
  "needs_email_confirmation": false,
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "v1.MRqX...",
  "token_type": "bearer",
  "user_id": "uuid-string",
  "expires_in": 3600,
  "message": "注册成功，已自动登录"
}
```

**邮箱确认模式响应（若未来开启 `enable_confirmations`）：** 不返回 token，`needs_email_confirmation=true`，提示用户查收邮件后走登录接口。

**错误：**

| 状态码 | 含义 | 前端处置 |
|:---:|---|---|
| `400` | 邮箱格式非法 / 密码不足 8 位 | 提示用户改输入 |
| `403` | 当前未开放注册（`signup_disabled` / `email_provider_disabled`） | 提示暂不开放，不必重试 |
| `409` | 该邮箱已注册，请直接登录 | 引导去登录 |
| `429` | 注册请求过于频繁（限流） | 稍后重试 |
| `500` | 数据库连接未就绪 | 服务端问题 |
| `502` | 未知服务异常 | 稍后重试 |
| `503` | 注册邮件通道未配置 | 服务端配置问题，重试无用 |

> `429` 在 2026-09-16 前曾被错误地归入 `502`，导致"配置问题"被当成"服务抖动"。若再次出现注册失败，**先看后端日志里的 `注册失败: code=...`**。

## 6. 退出登录

**方法 / 路径：** `POST /api/secure-chat/logout`（需 JWT）

**说明：** 撤销当前 access token（应用内存黑名单，**即时失效**）与 Supabase refresh token（服务端登出）。幂等操作：token 已失效或重复登出均返回成功。

**curl 示例：**

```bash
curl -X POST "$API/api/secure-chat/logout" \
  -H "Authorization: Bearer $TOKEN"
# 预期: {"success":true,"message":"退出登录成功"}
```

> 登出后原 token 立即返回 401「令牌已注销」，需重新登录获取新 token。黑名单仅存于应用内存，进程重启后未到期的 token 会恢复有效（本应用 token 有效期 1 小时，影响可接受）。

## 7. 注销账号

**方法 / 路径：** `POST /api/secure-chat/delete-account`（需 JWT）

**说明：** **不可逆操作**。先复核密码，再通过数据库函数单事务清理该用户全部业务数据（自选股、会话与消息、文档、风险画像与答题、持仓与流水、账户与快照、资产配置等），最后从 Supabase `auth.users` 删除账号。请求体需提交账号密码。

**请求体：**

| 字段 | 类型 | 必需 | 说明 |
|------|------|:---:|------|
| password | string | ✅ | 账号密码，用于复核（防止 token 被盗后随意删号） |

**curl 示例：**

```bash
curl -X POST "$API/api/secure-chat/delete-account" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"password\":\"$PASSWORD\"}"
# 预期: {"success":true,"message":"账号已注销"}
```

> ⚠️ 不可逆，请前端二次确认后再调用。密码错误返回 `401「密码错误」`。
