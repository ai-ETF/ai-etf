# 08 管理接口（/api/admin）

交易日历的人工刷新与核验。**不是用户接口**：不走 JWT，改用 `X-Admin-Token` 鉴权。

## 鉴权

服务端读取 `ADMIN_API_TOKEN` 环境变量，与请求头 `X-Admin-Token` 做常量时间比较：

- 未配置 `ADMIN_API_TOKEN`：所有管理接口返回 **503**（默认关闭）；
- 请求头缺失或值不匹配：返回 **401**；
- 鉴权通过后才进入业务逻辑。

## 前置条件

```bash
# 与服务端 ADMIN_API_TOKEN 保持一致；本目录其余模块的 $API / $AUTH 不适用于本文件
ADMIN_TOKEN="<ADMIN_API_TOKEN 的值>"
```

## 接口速查

| 方法 | 路径 | 认证 |
|------|------|:---:|
| POST | `/api/admin/trading-calendar/refresh` | `X-Admin-Token` |
| GET | `/api/admin/trading-calendar/status` | `X-Admin-Token` |

## 1. 刷新交易日历

**方法 / 路径：** `POST /api/admin/trading-calendar/refresh`（`X-Admin-Token`）

**说明：** 从单一数据源 `sina_trade_date` 全量抓取交易日，成功后一次 RPC 事务性整表替换，并原子替换进程内快照，**不需要重启服务**。失败时旧库与内存快照原样保留。

| 参数 | 位置 | 类型 | 默认 | 说明 |
|------|------|------|------|------|
| dry_run | query | bool | false | 只预览 diff，不写库、不替换内存 |
| Idempotency-Key | header | string | — | **必填**。仅用于日志追踪；整表替换天然幂等，重复调用不会产生重复数据 |
| X-Admin-Token | header | string | — | 管理凭证 |

```bash
# 预览 diff（不落库）——先确认覆盖区间和变更行符合预期
curl -s -X POST "$API/api/admin/trading-calendar/refresh?dry_run=true" \
  -H "X-Admin-Token: $ADMIN_TOKEN" \
  -H "Idempotency-Key: calendar-dryrun-20261102" | python3 -m json.tool

# 正式刷新
curl -s -X POST "$API/api/admin/trading-calendar/refresh" \
  -H "X-Admin-Token: $ADMIN_TOKEN" \
  -H "Idempotency-Key: calendar-refresh-20261102" | python3 -m json.tool
```

**响应要点：** `request_id`、`idempotency_key`、`dry_run`、`coverage_start`、`coverage_end`、`source`、`stats`（inserted / deleted / updated / unchanged）、`diff`（变更明细，最多返回截断后条数）、`diff_truncated`、`elapsed_ms`。

**错误语义：**

| 状态码 | 场景 |
|:---:|---|
| 400 | 缺少 `Idempotency-Key` |
| 401 | `X-Admin-Token` 缺失或错误 |
| 409 | 已有一轮刷新在跑（`RefreshInProgress`） |
| 422 | 上游返回数据不合法（`CalendarDataInvalid`），未写库 |
| 500 | 未预期的内部异常，未写库 |
| 502 | 数据源全部失败（非超时），未写库，响应体带 `capability` / `tried` |
| 503 | 服务端未配置 `ADMIN_API_TOKEN` |
| 504 | 上游超时（`CalendarRefreshTimeout` 或数据源超时），未写库 |

## 2. 核验交易日历状态

**方法 / 路径：** `GET /api/admin/trading-calendar/status`（`X-Admin-Token`）

**说明：** 只读核验，不访问上游数据源。返回进程内快照、DB 状态与行数统计，用于刷新后确认是否生效。

```bash
curl -s "$API/api/admin/trading-calendar/status" \
  -H "X-Admin-Token: $ADMIN_TOKEN" | python3 -m json.tool
```

**响应要点：**

| 字段 | 说明 |
|------|------|
| `ready` | 进程内快照是否已加载 |
| `coverage_start` / `coverage_end` | 覆盖区间（优先取 DB 的 `trading_calendar_state`） |
| `source` | 数据源标识，当前为 `sina_trade_date` |
| `last_success_at` / `last_error` / `last_error_at` | 最近一次成功刷新时间与失败信息 |
| `days` / `trading_days` | 覆盖区间内的自然日数 / 交易日数 |
| `snapshot` | 内存快照明细（未加载时为 `null`） |
| `state` | `trading_calendar_state` 原始行（无记录时为 `null`） |
| `db_error` | 仅 DB 读取失败时出现，不掩盖读取异常 |
| `request_id` | 本次请求的追踪 ID |
