# 02-风险测评

**被测模块**：`server/services/fund_risk_scores.py`、`server/services/risk_service.py`
**测试文件**：`tests/unit/server/services/test_fund_risk_scores.py`、`tests/unit/server/services/test_risk_service.py`
**测试方法**：纯函数直测 + `RiskService.__new__` 跳过 `__init__` 里的 `get_supabase()` 调用；全程不联网、不连 Supabase

## 功能

风险测评的两块纯逻辑：

1. **基金/用户风险等级计算与中文标签映射**（`fund_risk_scores.py`）—— 四维评分合成总分再映射到风险等级，等级 → 中文标签的展示映射。
2. **风险问卷画像计算**（`risk_service.py` 的纯逻辑部分）—— 答案校验、加权评分、等级判定、画像结果格式化。这些方法均不访问数据库，可脱离 Supabase 单独验证。

## 业务场景 / 预期结果 / 测试结果

### 一、`calc_risk_level` —— 四维总分 → 基金风险等级（6 例）

**业务场景**：基金风险由四个维度（指数广度 / 波动属性 / 市场属性 / 板块特征）各取 1–3 分相加得总分，再按阈值映射到 `moderate` / `aggressive` / `speculative`。

**预期结果**

| 场景 | 预期 |
|------|------|
| 总分 4（最低分） | `moderate` |
| 总分 5（恰好等于阈值） | `moderate` |
| 总分 6（越过 5 阈值） | `aggressive` |
| 总分 7（恰好等于阈值） | `aggressive` |
| 总分 8（越过 7 阈值） | `speculative` |
| 总分 12（最高分） | `speculative` |

**测试结果**：6 例全部通过。

### 二、`get_risk_label` —— 基金风险等级 → 中文标签（4 例）

**业务场景**：展示层把英文等级映射成中文标签；未知等级不应崩溃，原样返回。

**预期结果**

| 场景 | 预期 |
|------|------|
| `moderate` | `中等风险` |
| `aggressive` | `较高风险` |
| `speculative` | `高风险` |
| 未知等级 | 原样返回 |

**测试结果**：4 例全部通过。

### 三、`get_user_risk_label` —— 用户风险等级 → 中文标签（4 例）

**业务场景**：同上，映射用户画像等级；未知等级原样返回。

**预期结果**

| 场景 | 预期 |
|------|------|
| `conservative` | `保守型` |
| `moderate` | `稳健型` |
| `aggressive` | `进取型` |
| 未知等级 | 原样返回 |

**测试结果**：4 例全部通过。

### 四、`_build_warning_message` —— 风险提示文案（3 例）

**业务场景**：按提示级别（`info` / `warning` / `alert`）生成交易风险提示文案。`info` 仅作差异提示、不带配置比例；`warning` / `alert` 需嵌入建议配置比例。

**预期结果**

| 场景 | 预期 |
|------|------|
| `info` | 含「权益类投资产品」及两个等级标签，**不含** `%` |
| `warning` | 含 ⚠️ 与 `10%` 建议比例 |
| `alert` | 含 🔴 与 `5%` 建议比例 |

**测试结果**：3 例全部通过。

### 五、`_validate_answers` —— 答案校验（5 例）

**业务场景**：提交问卷前校验答案的完整性与合法性：数量一致、题目存在、不重复、选项值在合法范围内。

**预期结果**

| 场景 | 预期（返回 `(False, error)`） |
|------|------|
| 全部合法 | `(True, None)` |
| 答案数量与题目数不符 | `请回答全部 2 道题目` |
| 题目 id 不存在 | `题目 q9 不存在` |
| 重复作答 | `题目 q1 重复作答` |
| 选项值越界 | `题目 q1 的选项 "C" 无效，有效选项: A, B` |

**测试结果**：5 例全部通过。

### 六、`_calculate_score` —— 加权总分（5 例）

**业务场景**：按每题选中选项的 `risk_score × weight` 累加，除以权重和得加权总分；选项匹配不到时跳过该题；权重和为 0 时总分置 0。

**预期结果**

| 场景 | 预期 |
|------|------|
| 加权总分正常 | `(2×0.5 + 4×0.5) / 1.0 = 3.0`，含 2 条 weighted_scores |
| 选项匹配不到 | 跳过该题（weight 不计入），只剩 q2，总分 4.0 |
| 权重和为 0 | 总分 0 |
| 分数除不尽 | 四舍五入到 2 位（`4/3 → 1.33`） |
| 维度得分 | 有 `category` 用 category，否则用题目 id |

**测试结果**：5 例全部通过。

### 七、`_determine_risk_level` —— 用户风险等级判定（5 例）

**业务场景**：加权总分按阈值映射到 `conservative` / `moderate` / `aggressive`（阈值 1.6 / 2.4）。

**预期结果**

| 场景 | 预期 |
|------|------|
| 总分 = 1.6（阈值） | `conservative` |
| 总分 < 1.6 | `conservative` |
| 总分 1.61（越过 1.6） | `moderate` |
| 总分 = 2.4（阈值） | `moderate` |
| 总分 2.41（越过 2.4） | `aggressive` |

**测试结果**：5 例全部通过。

### 八、`_format_profile_result` —— 画像结果格式化（4 例）

**业务场景**：把入库的画像记录格式化为前端可见结构；`dimension_scores` 可能是 dict 或 JSON 字符串；字段缺失回退默认值。

**预期结果**

| 场景 | 预期 |
|------|------|
| 字段齐全 | 逐字段原样透出（`ai_summary` → `summary`） |
| `dimension_scores` 为 JSON 字符串 | 自动解析成 dict |
| `dimension_scores` 为非法 JSON | 回退 `{}` |
| 字段缺失 | `risk_level`/`risk_label`/`summary`/`created_at` → `""`，`total_score` → `0.0`，`dimension_scores` → `{}` |

**测试结果**：4 例全部通过。

## 测试过程中的观察（未改代码）

1. **`_calculate_score` 的「缺题跳过」**：实现是「选中选项匹配不到 → `continue` 跳过该题」。而「answer 里缺某题 `question_id`」会直接触发 `answer_map[qid]` 的 `KeyError`，并非跳过。因 `submit_answers` 中 `_validate_answers` 先行校验、生产不可达，本次未改代码、也未为该 KeyError 写断言，仅在此记录。
2. **`_validate_answers` 的「未回答题目」分支**：在「数量一致 + 题目不存在 / 重复作答」前序校验先行的前提下，该分支正常流程不可达，属防御性代码，未单独写断言。
3. 被测算例聚焦规划中的 8 个单元；同文件的 `_build_risk_warning`、`get_risk_warning`（查矩阵组装 dict）不在本次规划清单内，未覆盖。
