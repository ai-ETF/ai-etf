### B. 手续费与交易规则（10）

`server/services/fund_fee_service.py`。此模块决定**资金计算正确性**。

| 单元 | 说明 |
|------|------|
| `_match_purchase_tier` | 计算买入金额属于哪个档次的手续费：申购金额越大，费率越低、`inclusive` 边界（`<` vs `<=`）、无 `amount` 档位兜底、空档位默认费率 0.0015 |
| `calc_purchase_fee` | 计算你买入的 1000 元中有多少用来买基金，有多少用来交手续费。如果是 C 类，直接全额买基金 |
| `calc_redemption_fee` | 按持有天数匹配档位、边界天数 |
| `is_supported` | 白名单命中/未命中 |
| `get_fee_rule` | 单基金查询命中/未命中/DB 异常 |
| `get_fee_rules_batch` | 入参去重、查不到的基金不出现在结果中 |
| `get_min_purchase_amount` | 起购金额缺失时的返回值 |
| `get_confirm_delay` | 确认延迟天数 |
| `get_redeem_settle_delay` | 赎回到账延迟天数 |
| `get_fund_name` | 名称缺失时的兜底 |

> 规则来源：`fund_fee_rules` 表。**查不到规则即拒绝交易，不允许默认费率兜底** —— 测试需覆盖「查不到 → None / 拒绝」这一分支。

## 三、执行方式

每个模块按 `.claude/skills/unit-testing/SKILL.md` 的 SOP 执行：

1. **Step 1 确定测试目标** —— 依据本规划选定模块与单元；
2. **Step 2 代码检查与预期行为** —— 判断是否满足单测前提，不满足则提最小改造方案待批；随后列出正常/异常/边界三类预期行为；
3. **Step 3 编写测试代码** —— 遵循 AAA 原则，测试文件置于 `tests/unit/server/` 下并镜像源码目录结构；
4. **Step 4 生成测试结果文档** —— 在本目录生成 `NN-<模块名>.md` 记录业务场景、预期结果与测试结果。

> AI 不得因「代码看起来应该如此」而自行定义业务规则。若代码行为无法判断或存在多种合理预期，须向人确认。
