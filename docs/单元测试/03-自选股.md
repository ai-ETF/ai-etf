# 03-自选股

**被测模块**：`server/services/watchlist_service.py`
**测试文件**：`tests/unit/server/services/test_watchlist_service.py`
**测试方法**：替换 `svc._client` 为内存 `FakeClient`（支持 `select`/`insert`/`delete`/`eq`/`order`），行情用 monkeypatch 把 `FinanceApiService` 换成 `FakeFinanceApi`；全程不联网、不连 Supabase

## 功能

自选股的增、删、查、清：用户把 ETF 加入自选列表，可带实时行情查询。写入/读取走 Supabase 的 `watchlist` 表；`add`（名称缺失时）与 `list`（含行情时）会调 `FinanceApiService.query_spot` 拉实时行情。

## 业务场景 / 预期结果 / 测试结果

### 一、`_format_item` —— 单项格式化（2 例）

**业务场景**：把数据库记录格式化为前端结构，行情字段（`price`/`change_pct`/`change`）默认置空，由「含行情」的查询路径回填。

| 场景 | 预期 |
|------|------|
| 字段齐全 | 逐字段透出，三个行情字段均为 `None` |
| 字段缺失 | `id`/`fund_code` 等回退 `""`，`sort_order` 回退 `0` |

**测试结果**：2 例全部通过。

### 二、`add` —— 新增自选股（6 例）

**业务场景**：未传名称时自动拉行情补名称；已存在则拒绝；插入成功返回格式化条目。

| 场景 | 预期 |
|------|------|
| 正常新增（传名称） | `success=True`，item 的 `fund_code`/`fund_name` 正确 |
| 重复添加 | `success=False`，`该ETF已在自选列表中` |
| 名称缺失 | 调 `query_spot` 自动补名称 |
| 数据库不可用 | `success=False`，`数据库连接失败` |
| 异常（非唯一约束） | `success=False`，`添加失败: <err>` |
| 异常（唯一约束冲突） | `success=False`，`该ETF已在自选列表中` |

**测试结果**：6 例全部通过。

## 测试过程中的观察（未改代码）

1. **`datetime.utcnow()` 弃用**：[watchlist_service.py:65](server/services/watchlist_service.py#L65) 用了 `datetime.utcnow()`，Python 3.12 起才弃用（`DeprecationWarning`）。**项目当前运行于 Python 3.10，无需处理**；本观察仅作将来升级到 3.12 时的提醒（届时可改为 `datetime.now(timezone.utc)`）。
2. **`add` 的唯一约束冲突检测**：通过捕获异常并匹配错误信息里的 `duplicate`/`unique` 关键词来判断「已存在」。测试用带 `duplicate` 的 `RuntimeError` 触发了这条映射分支，验证其行为符合预期。
