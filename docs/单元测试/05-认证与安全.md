# 05-认证与安全

**被测模块**：`server/services/auth_service.py`、`server/auth/deps.py`
**测试文件**：
- `tests/unit/server/services/test_auth_service.py`
- `tests/unit/server/auth/test_deps.py`

**测试方法**：monkeypatch `get_supabase` / `revoke` / `verify_supabase_token` / `is_revoked`，用 `FakeSupabase` 替身覆盖 `auth`/`rpc` 子接口；全程不联网、不连 Supabase。

## 功能

认证与安全链路的两块：`auth_service` 负责注册（含参数校验与 Supabase 异常 → HTTP 状态码映射）、退出登录（撤销 token）、注销账号（密码复核后清理业务数据并删号）；`deps` 提供 FastAPI 依赖，从 `Authorization` 头提取并校验 JWT，返回 `user_id`。

## 业务场景 / 预期结果 / 测试结果

### 一、`validate_email` —— 邮箱格式（3 例）

**业务场景**：轻量正则校验邮箱格式，非法抛 400。

| 场景 | 预期 |
|------|------|
| 合法邮箱 | 不抛异常 |
| 非法邮箱 / 空字符串 | 抛 400 |

**测试结果**：3 例全部通过。

### 二、`validate_password` —— 密码长度（3 例）

**业务场景**：应用层强制密码 ≥ 8 位，不足抛 400。

| 场景 | 预期 |
|------|------|
| 8 位 | 通过 |
| 7 位 / 空 | 抛 400 |

**测试结果**：3 例全部通过。

### 三、`register_user` —— 注册（10 例）

**业务场景**：校验通过后调 Supabase `sign_up`；把各种 Supabase 异常映射为对应 HTTP 状态码。

| 场景 | 预期 |
|------|------|
| 注册成功 | 返回 `{session, user}` |
| 邮箱已存在（`user_already_exists`） | 409 |
| 邮箱格式错误（应用层） | 400 |
| 密码过短（应用层） | 400 |
| 数据库未就绪 | 500 |
| 密码过弱（`AuthWeakPasswordError`） | 400 |
| `email_address_invalid` | 400 |
| `weak_password` | 400 |
| 其他 AuthApiError（限流等） | 502 |
| 未知异常 | 502 |

**测试结果**：10 例全部通过。

### 四、`logout_user` —— 退出登录（3 例）

**业务场景**：先本地撤销 access token（立即失效），再调 Supabase 撤销 refresh token；Supabase 侧失败不阻塞。

| 场景 | 预期 |
|------|------|
| 正常 | `revoke(token, exp)` 被调用 + `sign_out(token, "global")` 被调用 |
| 数据库未就绪 | 仍本地撤销，不报错、跳过 Supabase |
| `sign_out` 抛异常 | 不阻塞返回（幂等） |

**测试结果**：3 例全部通过。

### 五、`delete_account` —— 注销账号（5 例）

**业务场景**：先用邮箱+密码重新登录复核身份（防 token 被盗用者删号），再 RPC 清理业务数据、删除 auth 账号。

| 场景 | 预期 |
|------|------|
| 数据库未就绪 | 500 |
| 密码错误 | 401 |
| 成功 | `purge_user_data(user_id)` 被调用 + `delete_user(user_id)` 被调用 |
| 清理业务数据失败 | 502 |
| 删除账号失败 | 502 |

**测试结果**：5 例全部通过。

### 六、`extract_and_verify` —— 提取并验证 JWT（4 例）

**业务场景**：从 `Authorization` 头提取 Bearer token，验证有效性并拦截已注销 token。

| 场景 | 预期 |
|------|------|
| 缺少 Bearer 前缀 | 401（提示 `Bearer`） |
| 令牌无效 | 401 |
| 令牌已撤销 | 401（提示「注销」） |
| 成功 | 返回 `(token, payload)` |

**测试结果**：4 例全部通过。

### 七、`get_current_user` —— 取当前用户（2 例）

**业务场景**：从校验后的 payload 取 `sub`（用户 UUID）。

| 场景 | 预期 |
|------|------|
| payload 含 `sub` | 返回 `user_id` |
| payload 无 `sub` | 401 |

**测试结果**：2 例全部通过。

## 运行方式

```bash
poetry run pytest tests/unit/server/services/test_auth_service.py \
                     tests/unit/server/auth/test_deps.py -v
# 含覆盖率
poetry run pytest tests/unit/server/services/test_auth_service.py \
                     tests/unit/server/auth/test_deps.py \
  --cov=server.services.auth_service --cov=server.auth.deps --cov-report=term-missing
```

> 本次 30 例全部通过。覆盖率：`deps.py` 21 语句、0 未覆盖（**100%**）；`auth_service.py` 77 语句、1 未覆盖（**99%**）。
> 未覆盖的第 157 行是 `delete_account` 中**第二次** `get_supabase()` 返回 `None` 的 500 分支——`get_supabase()` 每次调用都按当前环境变量重新建客户端，两次调用一次成功一次失败仅在环境变量中途变化或建连瞬时失败时发生，属防御性分支，未专门构造该场景。
