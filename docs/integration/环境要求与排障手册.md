## 〇、结论速览

环境齐备只需要三样东西：**Docker（含权限）+ 本地 Supabase 栈（含种子数据）+ poetry 环境**。

另外有**一样 git 里拿不到**（本地嵌入模型，见 §2.4）、**两样必须"没有"**（外网、非本地库，见 §三）。

`.env` **不需要配** —— 依据见 §1.3。

如果测试能跑起来但有一批用例始终不通过，**别在环境上找原因**：见 **附录 B**，那 7 条已定位，与环境无关。

## 一、环境要求

### 1.1 必需项

| # | 要求 | 为什么 | 少了会怎样 |
|---|---|---|---|
| 1 | **Docker**（`docker.io`），且当前用户在 `docker` 组 | 本地 Supabase 栈跑在容器里 | 栈起不来 / 报 socket 权限错误 |
| 2 | **本地 Supabase 栈**在跑（`http://127.0.0.1:54321`，用本地 `service_role` key） | 集成测试连的就是它；只需 db + postgrest + auth 三个服务 | 会话直接退出，报「集成测试缺少 Supabase URL」 |
| 3 | **种子数据已灌入**（`supabase/seed.sql`：21 条费率规则 + 问卷等） | `FundFeeService` 查不到规则会直接拒单 | 交易链路整块失败 |
| 4 | **poetry 环境**（`poetry install`，含 dev 组） | 运行入口 | 命令都跑不起来 |
| 5 | ⚠️ **本地嵌入模型 `local_models/text2vec-base-chinese`** | pgvector / RAG / 上传三类用例要真实嵌入 | 这些用例报模型加载失败 —— **该目录被 `.gitignore` 排除，clone 拿不到** |
| 6 | **在仓库根目录下执行 pytest** | 模型路径是相对路径 `./local_models/...` | 同上，表现为「模型不存在」 |

### 1.2 明确**不需要**的

| 项 | 说明 |
|---|---|
| **外网** | 不但不需要，而且**被禁止**（§3.1）。AKShare 走录制样本回放，LLM 用假对象。连不上行情接口不是问题 |
| **生产库 / 线上环境** | **被硬拦**（§3.2） |
| **真实 Anthropic API key** | 只有 `-m eval` 那 2 条要用；默认不跑（§4.3） |

### 1.3 关于 `.env`：集成测试不读它

**结论：不配 `.env` 也能跑通集成测试。**

依据（实测）：跑测试时进程日志里明确出现

```
WARNING root:settings.py:31 未配置SUPABASE_URL环境变量
WARNING root:settings.py:33 未配置SUPABASE_SERVICE_ROLE_KEY环境变量
INFO  server.app:app.py:73 Supabase连接验证成功
```

环境变量没配，但连接验证照样成功 —— 因为用例自己把数据库客户端指向本地栈，JWT 也是自己签的（见 §1.4）。

**唯一例外**是 `tests/integration/server/test_llm_eval.py`（`eval` 标记，2 条）：它需要真实的 `ANTHROPIC_API_KEY`，没配就 `pytest.skip`。

### 1.4 连库信息与鉴权从哪来（不必干预，但需要知道）

`tests/integration/conftest.py` 按此优先级自行解析：

1. 环境变量 `TEST_SUPABASE_URL` / `TEST_SUPABASE_SERVICE_ROLE_KEY`（**留给 CI 的口子**）
2. 未设置则调用 `supabase status -o env`，读 `API_URL` 与 `SERVICE_ROLE_KEY`
3. JWT secret 同理；都取不到时回落到 supabase 的公开默认值

`supabase status` 需要 docker socket 权限；若当前用户不在 docker 组，conftest 会用 `sg docker -c "..."` 包一层兜底 —— 手工排障时也可以用同样的手法。

鉴权不依赖真实登录流程：用例用本地 JWT secret **自签 HS256 token**，直接覆盖所有 `Depends(get_current_user)` 路由。

## 二、从零搭起来

### 2.1 装 Docker

```bash
sudo apt update && sudo apt install -y docker.io
sudo usermod -aG docker $USER     # 需重开 shell 或 wsl --shutdown 后重进才生效
newgrp docker                     # 当前会话临时生效
docker ps                         # 能列出（空表亦可）即成功
```

`docker ps` 报权限错误时，把命令套一层：`sg docker -c "docker ps"`。

### 2.2 起本地 Supabase 栈

```bash
cd <ai-etf 仓库根>
supabase start -x realtime,storage-api,imgproxy,edge-runtime,logflare,vector,supavisor,studio,analytics
supabase status
```

- `supabase` 命令未安装：`npm i -g supabase`。
- `-x` 是裁掉用不到的服务 —— 测试只需 **db + postgrest + auth**，全栈在 8 GiB 内存的机器上偏紧。
- `supabase status` 能打印出 `API_URL=http://127.0.0.1:54321` 即表示已就绪。
- **种子数据是自动灌入的**：`supabase start`（首次）与 `supabase db reset` 都会重放迁移 + `supabase/seed.sql`。该文件**已入库**，正常 clone 即具备；本地库中应有 **21 条** `fund_fee_rules`。

**若卡在拉镜像**：实测 `registry-1.docker.io` **不通**，但 `public.ecr.aws`、`ghcr.io` **通**；supabase CLI 主要从 `public.ecr.aws` 拉取，**通常无需配镜像**。确实要配时写入 `/etc/docker/daemon.json`（改完 `sudo systemctl restart docker`）：

```json
{ "registry-mirrors": ["https://docker.m.daocloud.io", "https://docker.1panel.live"] }
```

> 这两个是实测可达的；`hub-mirror.c.163.com`、`mirror.ccs.tencentyun.com` 已失效，不必再试。

### 2.3 装 python 依赖

```bash
cd <ai-etf 仓库根>
poetry install
```

dev 组会自动装上 `pytest` / `pytest-asyncio` / `pytest-cov` / `time-machine`（见 `pyproject.toml` 的 `[dependency-groups]`）。

按仓库约定：**用 poetry 管依赖，不用 pip，不直接改环境文件**；跑测试统一走 `poetry run pytest`。

### 2.4 补本地嵌入模型（⚠️ 最容易被漏的一步）

`local_models/` 被 `.gitignore` 排除，**不在仓库里**，需要自行补上：

- 目录：`local_models/text2vec-base-chinese/`，约 **470 MB**（`model.safetensors` 单文件约 409 MB）
- 代码逻辑（[embedder.py:28](../../server/rag/embedder.py#L28)）：该目录**存在**就从本地加载；**不存在**则去 HuggingFace 拉 `shibing624/text2vec-base-chinese`
- 而测试里设了 `TRANSFORMERS_OFFLINE=1` / `HF_HUB_OFFLINE=1`，HuggingFace 又连不上 ⇒ **直接失败**
- 至少需要这 4 个配置文件，缺了会报 `Unrecognized processing class`：
  `vocab.txt`、`tokenizer_config.json`、`special_tokens_map.json`、`sentence_bert_config.json`
- 获取方式：从能联网的机器下载；或从已跑通的机器整目录拷贝

**依赖嵌入的用例**（这 3 个文件里也正是因为如此才设了离线环境变量）：
`tests/integration/server/storage/test_embedding_repo_pgvector.py`、`rag/test_rag_pipeline.py`、`pipeline/test_upload_e2e.py`。

## 三、两条「反向」约束（不是缺环境，是故意不让做）

### 3.1 不需要外网，而且禁止外网

`tests/integration/conftest.py` 有一个自动生效的守卫，在 `socket.socket.connect` 这一层拦掉所有非 `127.0.0.1` / `localhost` / `::1` 的连接，命中即抛：

```
RuntimeError: 集成测试禁止出网：<IP>。外部 API（AKShare/LLM）须用录制回放或假对象隔离。
```

⇒ 测试期间**不需要也不能**联外网：行情走录制样本（`tests/integration/fixtures/akshare/spot_sample.pkl`），LLM 用假对象。

**看到这条报错不要当成环境故障** —— 它出现说明守卫在正常工作，通常是某条用例走到了真实外部 API。

### 3.2 只许连本地栈

conftest 启动时会断言连库地址必须是 localhost，否则**整个测试会话直接退出**（`pytest.exit(returncode=3)`）：

```
拒绝连接非本地 Supabase（<URL>）——集成测试只允许连本地栈，防止误写生产库
```

这条防的是误连生产库，**是设计而非缺陷**。

## 四、怎么跑

### 4.1 命令

```bash
cd <ai-etf 仓库根>
poetry run pytest -m integration tests/integration
```

### 4.2 两个必踩的坑

**坑 1：必须显式写 `-m integration`。**
`pyproject.toml` 里默认是 `addopts = "-m 'not integration and not eval'"`，不加 `-m` 时集成用例会被**全部排除**，输出形如：

```
collected 3 items / 3 deselected / 0 selected
```

（实测：直接跑冒烟文件就是 0 selected。）

**坑 2：必须带上路径 `tests/integration`。**
全仓执行 `poetry run pytest -m integration` 会在**收集阶段**就报错中断：

```
import file mismatch: ... test_fund_catalog_sync.py ... which is not the same as the test file we want to collect
```

原因：`tests/unit` 与 `tests/integration` 下**各有一个同名的** `test_fund_catalog_sync.py`，而仓库里只有 `tests/__init__.py`，子目录都不是包 ⇒ pytest 默认导入方式撞名。
带上路径即正常（实测收集到 **90 例**）。要根治需给子目录补 `__init__.py` 或调整 `importmode`，**当前未做**。

### 4.3 marker 分组现状（与 `00` 文档 §8.2 不一致，以本节为准）

`pyproject.toml` 声明了 5 个 marker，**实际只用到两个**：

| marker | 实际使用情况 |
|---|---|
| `integration` | ✅ 集成测试全用它（`tests/integration` 下 92 条） |
| `eval` | ✅ 2 条（`test_llm_eval.py`），跑 `-m integration` 时被排除 |
| `integration_db` | ❌ **没有任何用例使用** ⇒ `-m integration_db` 跑出来是空的 |
| `integration_net` | ⚠️ 仅 1 处：`tests/contract/test_frontend_contract.py` 的 C4（且它需要真实后端在运行） |

## 六、现象 → 原因 → 处置

| 现象 / 报错 | 原因 | 处置 |
|---|---|---|
| `集成测试缺少 Supabase URL`（会话直接退出） | 本地栈没起，或 `supabase` 不在 PATH | `supabase start`；`which supabase` |
| `拒绝连接非本地 Supabase (...)` | 连库地址指向了非本机（是否设了 `TEST_SUPABASE_URL`？） | 清掉该变量，让它回落到 `supabase status` |
| `permission denied ... /var/run/docker.sock` | 当前用户不在 docker 组 | `sudo usermod -aG docker $USER` 后**重开 shell**；或命令前套 `sg docker -c "..."` |
| 卡在拉镜像 / `i/o timeout` | Docker Hub 不通 | 配镜像加速器（§2.2）；先确认 `public.ecr.aws` 是否可达 |
| `collected N items / N deselected / 0 selected` | 忘了 `-m integration` | 见 §4.2 坑 1 |
| 收集阶段 `import file mismatch` 中断 | 命令没带 `tests/integration` 路径 | 见 §4.2 坑 2 |
| `集成测试禁止出网：<IP>` | 某条用例走到了真实外部 API | 守卫在正常工作；检查新写的用例是否隔离了外部依赖 |
| `Unrecognized processing class` / 离线模式下加载模型失败 | `local_models/text2vec-base-chinese/` 未补，或缺那 4 个配置文件 | 见 §2.4 |
| 其余都正常但仍报模型不存在 | 不在仓库根目录执行 | `cd` 到仓库根再跑（路径是相对的） |
| 交易相关用例失败、日志提示查不到费率规则 | 种子数据没灌（库是空的） | `supabase db reset` 重放迁移 + seed |
| `invalid input syntax for type uuid: "..."` | 用例传的 user_id 不是 UUID | 非环境问题，见附录 B |
| 完整跑时偶发几条 ERROR，单跑即正常 | 资源竞争（torch + supabase + docker exec 争抢 CPU/内存） | 重跑，或按文件分批跑 |
