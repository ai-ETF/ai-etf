## 二、集成测试的 CI job 是什么

一句话：**在 GitHub 的 Ubuntu 机器上，先起一个本地 Supabase（Docker），再把 `pytest -m integration` 跑一遍，失败就让这次 push/PR 变红。**

它和 E2E 的区别：E2E 要 Windows + 微信开发者工具图形界面，跑不了；集成测试只依赖 Linux + Docker，**可以跑**。它和契约测试的区别：契约测试不碰数据库、秒级；集成测试要起真实 Postgres + pgvector，分钟级。

### 2.1 工作流文件（2026-10-17 已创建）

已落地为 [`.github/workflows/integration-tests.yml`](../../.github/workflows/integration-tests.yml)，**只监听 `workflow_dispatch`（手动触发）**。稳定前不挂 `push` / `pull_request`，避免 7 条固定失败制造长期红灯。下面是同一份内容，便于阅读：

```yaml
name: 集成测试

# ⚠️ 目前只允许手动触发。7 条固定失败（见 §四）处理完再加 push / pull_request。

on:
  workflow_dispatch:

jobs:
  integration:
    runs-on: ubuntu-latest
    timeout-minutes: 40

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: 安装 poetry
        run: pipx install poetry==2.4.1

      - name: 虚拟环境落在仓库内（便于缓存）
        run: poetry config virtualenvs.in-project true

      - name: 缓存虚拟环境
        uses: actions/cache@v4
        with:
          path: .venv
          key: venv-${{ runner.os }}-py3.12-${{ hashFiles('poetry.lock') }}

      - name: 安装依赖
        run: poetry install --no-root

      # local_models/ 被 .gitignore 排除，clone 拿不到；491 MB，必须单独准备。
      - name: 缓存嵌入模型
        uses: actions/cache@v4
        with:
          path: local_models/text2vec-base-chinese
          key: text2vec-base-chinese-v1

      - name: 下载嵌入模型（缓存未命中时）
        run: |
          if [ ! -f local_models/text2vec-base-chinese/model.safetensors ]; then
            poetry run python - <<'PY'
            from huggingface_hub import snapshot_download
            snapshot_download(
                "shibing624/text2vec-base-chinese",
                local_dir="local_models/text2vec-base-chinese",
            )
            PY
          fi

      - name: 安装 Supabase CLI
        uses: supabase/setup-cli@v1
        with:
          version: 2.114.0

      # 只起测试用到的服务，省内存（runner 约 7 GB）。
      - name: 启动本地 Supabase 栈
        run: supabase start -x realtime,storage-api,imgproxy,edge-runtime,logflare,vector,supavisor,studio,analytics

      - name: 导出本地栈连接信息
        run: |
          eval "$(supabase status -o env)"
          echo "TEST_SUPABASE_URL=$API_URL" >> "$GITHUB_ENV"
          echo "TEST_SUPABASE_SERVICE_ROLE_KEY=$SERVICE_ROLE_KEY" >> "$GITHUB_ENV"

      - name: 跑集成测试
        run: poetry run pytest -m integration tests/integration -q
```

## 三、需要准备的东西（2026-10-17 核对）

| 项 | 结论 | 说明 |
|---|---|---|
| **Docker** | ✅ 本机已装并可用（`docker version` 29.1.3）；GitHub `ubuntu-latest` 自带 | 本地 Supabase 栈靠它 |
| **本地 Supabase 栈** | ✅ 可用（`supabase` CLI 2.114.0，栈曾实测跑通） | 用 `-x` 裁掉不用到的服务，7.6 GiB 机器够用 |
| **种子数据** | ✅ `supabase/seed.sql` 存在（21 条费率规则） | `supabase start` 会自动执行迁移 + seed；**不再需要手工灌数**。注意：`00` 文档 §5.3 说「该文件不存在」已过期 |
| **嵌入模型** | ⚠️ 需要 CI 单独下载（491 MB，`local_models/` 被 `.gitignore` 排除） | 已写进草案的「缓存 + 下载」两步 |
| **内存** | ✅ 本机 7.6 GiB（可用 5.3 GiB）；runner 约 7 GiB | 裁剪服务后能跑；如果 OOM，再减 `-x` 清单里的服务 |
| **连接信息 / secrets** | ✅ **不需要 secrets** | 本地栈的 URL / service_role key 由 `supabase status` 现场生成，`conftest.py:43-56` 优先读 `TEST_SUPABASE_URL`，没有就调 CLI。**不要**把生产库的 key 放进 secrets |
| **JWT secret** | ✅ 自动获取（`conftest.py:228-242`） | 自签 token 用本地栈的 secret |
| **网络** | ✅ 测试期间禁止出网，不需要外网 | 唯一需要联网的是「下载嵌入模型」这一步，它在测试开始前 |

> 如果以后改成连「托管的测试库」而不是本地栈，才需要 `TEST_SUPABASE_URL` / `TEST_SUPABASE_SERVICE_ROLE_KEY` 两个 secrets；并且 conftest 的「只许连 localhost」断言会直接拒绝（`conftest.py:82-90`），要改断言规则才能用。**当前不建议这么做。**

## 五、已知风险

- `sql_delete_auth_user`（`conftest.py:272-300`）用 `sg docker -c "docker exec supabase_db_ai-etf ..."` 清理注册用户：容器名依赖 `supabase/config.toml` 的 `project_id = "ai-etf"`；runner 上必须有 `sg` 命令。若 CI 报「sg: command not found」，需要给该 fixture 加 `docker exec` 直接兜底（改测试代码，需评审）。
- 首次跑要拉 Supabase 镜像，可能 10–20 分钟；缓存镜像不是默认能力，先用 `timeout-minutes: 40` 兜住。
- 集成测试是**串行**的（共享本地库），不要加 `-n auto`；并发会互相清数据。
- ⚠️ **每条 API 用例都会调用一次 `supabase status -o env`**（`conftest.py` 里的库地址 / JWT secret 解析），本机实测单次约 2 秒，90 条下来会多出几分钟。`TEST_SUPABASE_URL` / `TEST_SUPABASE_SERVICE_ROLE_KEY` 只能省掉其中一个调用；JWT secret 那条目前只认 CLI。**不阻塞 CI，但要知道「测试看起来很慢」不是用例本身慢。**
- seed 的生效时机是「迁移之后、db reset 时」（`supabase/config.toml` 的 `[db.seed]`）。CI 上如果发现 `fund_fee_rules` 是空的，先跑一次 `supabase db reset` 再确认；不要手工灌数据。
