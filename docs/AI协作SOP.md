# Vibe Coding 协作协议

> **权威文件在**：`.claude/skills/ai-collaboration/SKILL.md`
> 本页只是索引，避免规则两处维护产生漂移（见反模式「同一概念两套实现」）。

**最高原则**：让设计、代码实现和人的决策始终显式同步——AI 不能只在自己脑子里开发。

**一句话**：先理解现状，再动手；一切结论落文档，文档是唯一的 backlog。

**怎么用**

| 方式 | 说明 |
|---|---|
| 输入 `/ai-collaboration` | 显式加载协议 |
| 说「按 SOP 协作 / 文档驱动 / 先设计后实现」 | 同上 |
| 日常对话 | 若 skill 未被自动加载，可要求我读 `.claude/skills/ai-collaboration/SKILL.md` |

**这不是流程，是六个关键转折点**

```
① 用户提出业务需求   →  先读现状相关实现，不直接改代码
② 准备动手写代码     →  必须先有文档
③ 存在明显的方案取舍  →  编号选项 + 代价 + 推荐，交人拍板
④ 实现中推翻原设计   →  先改文档，再改代码
⑤ 撞上范围外的问题   →  默认只记录，不顺手修
⑥ 完成一轮修改       →  会话汇报 + 回填文档真实状态
```

实际跑通并验证有效的做法，例子均取自该轮。
