# 基金订单确认规则（10:00 确认）

> 本文定义**成交净值日**、**确认时点**、**赎回到账**与**撤单窗口**四项业务口径，是需求输入。
> 状态机、资金记账、RPC 与调度实现见
> [订单确认：业务规则](../20-设计/基金与交易/订单确认-业务规则.md)；
> 扫描/重试/幂等见 [订单确认-执行机制](../20-设计/基金与交易/订单确认-执行机制.md)；
> 旧调度口径见 [订单确认（需求）](订单确认.md)。

## 0. 一句话规则

> **成交净值日 = 受理日；确认时点 = 受理日 + N 个交易日的 10:00；赎回款 = 实际确认日 + 1 个交易日的 10:00 入现金；撤单截止 = 受理日 15:00。**
>
> 普通基金 `N = 1`，QDII 基金 `N = 2`。15:00 是受理日的分界线，10:00 是确认与到账的执行时点。

## 1. 术语与时间口径

| 术语 | 定义 |
|---|---|
| 交易日 | A 股交易日：周一至周五且非法定节假日，以 `server/services/trading_calendar` 的日历快照为唯一来源 |
| 15:00 分界线 | 交易日 `15:00:00`（`Asia/Shanghai`）。**早于 15:00 算当日；15:00 整及之后一律顺延到次一交易日** |
| 受理日 `accepted_date` | 订单归属的交易日，**同时就是成交净值日** |
| 成交净值日 `nav_date` | 计算买入份额 / 卖出金额所用的净值日期，恒等于受理日 |
| 确认日 `confirm_date` | 系统执行确认的交易日 = 受理日 + `N` 个交易日 |
| 确认时点 | 确认日当天 `10:00`（`Asia/Shanghai`），批量确认任务触发 |
| 赎回到账日 `settle_date` | 赎回款转为可用现金的交易日 = **实际确认日** + 1 个交易日 |
| 到账时点 | 到账日当天 `10:00`（`Asia/Shanghai`），批量到账任务触发 |
| 撤单截止 | 受理日当天 `15:00:00`（`Asia/Shanghai`）；仅截止前允许撤单 |
| `N` | 普通基金 `1`，QDII 基金 `2`；以基金费率规则的 `confirm_delay` 字段为准，缺失时快速失败，不默认兜底 |

### 1.1 计算顺序

```text
accepted_date = if 下单日 == 交易日 and 下单时刻 < 15:00
                then 下单日
                else 下一个交易日

nav_date       = accepted_date
confirm_date   = accepted_date + N 个交易日     # 普通 N=1，QDII N=2
confirm_at     = confirm_date 当天 10:00:00 (Asia/Shanghai)

settle_date    = 实际确认日 + 1 个交易日
settle_at      = settle_date 当天 10:00:00 (Asia/Shanghai)

cancel_deadline = accepted_date 当天 15:00:00 (Asia/Shanghai)
```

### 1.2 硬约束

1. **确认不得早于确认日 10:00。** 即使 T 日净值在前一交易日晚间已同步落库，也不得提前确认。
2. **确认必须使用成交净值日（受理日）的净值。** 该日净值未公布时保持 `pending`，**不得用邻近交易日的净值顶替**，也不因此拒单。
3. **赎回款不得早于实际确认日之后 1 个交易日入现金。** 确认只生成应收，不加 `cash`。
4. **撤单只允许在受理日 15:00 前。** 15:00 整及之后不可撤单。
5. 所有时间按 `Asia/Shanghai` 解释，不依赖服务器本地时区。
6. `T+1`、`T+2` 中的 `+N` 一律指**交易日**，不是自然日。
7. **本期不处理货币基金**（净值恒 1.0000）。其确认与到账口径另行规定，不套用本文的 `N` 与到账规则。

### 1.3 为什么普通基金与 QDII 的确认延迟不同

确认延迟由两个因素共同决定：**成交净值日（T 日）的净值何时可得**，以及**份额登记周期**。

| 类型 | T 日净值可得时点 | 份额登记 | 确认时点 |
|---|---|---|---|
| 普通基金（境内） | T 日晚上（通常当晚公布） | T+1 | T+1 日 10:00 |
| QDII·美股 | T+1 日晚上（美股收盘与净值公布晚于北京时间） | T+2 | T+2 日 10:00 |
| QDII·港股 | 无时差，T 日晚上即可得 | 仍为 T+2 登记 | T+2 日 10:00 |

结论：

1. **普通基金**：T 日晚拿到 T 日净值，T+1 日 10:00 即可确认，所以 `N = 1`。
2. **QDII·美股**：因时差，T 日净值要到 T+1 日晚上才拿得到，T+1 日白天无法确认，只能 `N = 2`，在 T+2 日 10:00 确认。
3. **QDII·港股**：虽然无时差、T 日净值更早可得，但份额登记周期仍是 T+2，**净值早到也不得提前确认**，统一 `N = 2`。
4. 净值**早到不改变确认日**；净值**晚到只让订单保持 `pending` 重试**，不改变成交净值日，也不改变应确认日。

> **美股交易日与 A 股交易日不一致**：美股 QDII 在确认日 10:00 仍拿不到受理日净值时，**允许顺延到下一交易日 10:00 确认**，按此逐日顺延直至净值可用。顺延只影响执行时点，不改变成交净值日，也不得用其他日期的净值顶替。

### 1.4 非交易日下单

非交易日（周末、法定节假日）全天下的单，受理日为**下一个交易日**，等同于该交易日 15:00 之前下的单：

| 下单时间 | 普通基金受理日 | 普通基金确认时点 |
|---|---|---|
| 周六任意时刻 | 下周一 | 下周二 10:00 |
| 国庆假期任意时刻 | 节后首个交易日 | 节后第二个交易日 10:00 |

QDII 同理，确认日在受理日基础上再顺延 2 个交易日。非交易日下单的撤单截止，同样是**受理日 15:00**。

## 2. 普通基金（非 QDII）

### 2.1 买入

| 下单时间 | 受理日 / 成交净值日 | 确认时点 |
|---|---|---|
| 交易日 15:00 前 | 当日 T | T+1 交易日 10:00 |
| 交易日 15:00 及之后 | 次一交易日 T+1 | T+2 交易日 10:00 |
| 非交易日任意时刻 | 下一交易日 | 再下一交易日 10:00 |

### 2.2 卖出（含到账）

卖出与买入采用**同一套受理日与确认延迟**：`N = 1`。赎回款在**实际确认日再往后 1 个交易日**入现金。

| 下单时间 | 受理日 / 成交净值日 | 确认时点 | 现金到账时点 |
|---|---|---|---|
| 交易日 15:00 前 | 当日 T | T+1 交易日 10:00 | T+2 交易日 10:00 |
| 交易日 15:00 及之后 | 次一交易日 T+1 | T+2 交易日 10:00 | T+3 交易日 10:00 |
| 非交易日任意时刻 | 下一交易日 | 再下一交易日 10:00 | 确认日再往后 1 个交易日 10:00 |

## 3. QDII 基金

QDII 基金确认延迟为 `N = 2`，其余规则（15:00 分界线、非交易日顺延、按受理日净值成交、到账加 1 个交易日）不变。

`N = 2` 不是只按「QDII」这个标签简单拍定：

- **美股 QDII**：T 日净值要到 T+1 日晚上才拿得到，T+1 日 10:00 时无净值可用，因此只能在 T+2 日 10:00 确认；若届时仍无净值，允许顺延到下一交易日。
- **港股 QDII**：无时差，T 日晚上就能拿到净值，但份额登记周期仍为 T+2，因此同样不得提前确认。

两类 QDII 的确认时点一致，但理由不同，实现与客服口径都不应把 `N = 2` 解释成「QDII 一律晚一天」。

### 3.1 买入

| 下单时间 | 受理日 / 成交净值日 | 确认时点 |
|---|---|---|
| 交易日 15:00 前 | 当日 T | T+2 交易日 10:00 |
| 交易日 15:00 及之后 | 次一交易日 T+1 | T+3 交易日 10:00 |
| 非交易日任意时刻 | 下一交易日 | 再往后 2 个交易日 10:00 |

### 3.2 卖出（含到账）

| 下单时间 | 受理日 / 成交净值日 | 确认时点 | 现金到账时点 |
|---|---|---|---|
| 交易日 15:00 前 | 当日 T | T+2 交易日 10:00 | T+3 交易日 10:00 |
| 交易日 15:00 及之后 | 次一交易日 T+1 | T+3 交易日 10:00 | T+4 交易日 10:00 |

## 4. 收益归属

### 4.1 买入

- 份额在**确认日 10:00 确认后**才计入持仓，从确认日当日起参与净值涨跌。
- 确认日之前（含受理日当天及中间等待日）不享有收益。

### 4.2 卖出

- 卖出按**受理日（T 日）净值**成交，卖出方**享有 T 日收益**——T 日净值涨跌归卖出方。
- 从 T 日之后的交易日起，该笔份额不再享有净值涨跌。
- 卖出 pending 期间份额冻结，仅用于防止重复卖出；**冻结不等于继续享有收益**。
- QDII 卖出同样：虽然 T+2 日才确认，但成交净值为 T 日净值，**只享有 T 日收益，不享有 T+1、T+2 日收益**。
- 确认后到账前的在途期间，赎回款不计收益。

## 5. 撤单规则

### 5.1 窗口

| 下单时间 | 撤单截止 | 说明 |
|---|---|---|
| 交易日 15:00 前 | **当天（T 日）15:00 前** | 撤单窗口与受理日同一天 |
| 交易日 15:00 及之后 | **T+1 交易日 15:00 前** | 订单受理日已是 T+1，撤单截止同步顺延 |
| 非交易日任意时刻 | **下一交易日 15:00 前** | 受理日顺延，撤单截止跟随 |

- `15:00:00` 整及之后不可撤单（与下单截止的分界一致）。
- `T+1` 指交易日，不是自然日；遇周末、节假日顺延到下一个交易日 15:00。
- 以服务端时钟（`Asia/Shanghai`）为准，不信任客户端时间。

### 5.2 可撤条件与状态流转

- 订单状态必须为 `pending`，这是撤单的**唯一入口**。
- 状态流转：`pending → cancelled`，`cancelled` 为终态。
- `processing`（确认中）、`manual_review`（待人工）、`settling`（卖出待收款）、`completed`、`rejected`、`settled` **均不可撤**。
- 已撤单（`cancelled`）的订单再次撤单：幂等返回成功，不重复退款、不重复释放份额。
- 不做部分撤单，一笔订单只能整笔撤销。

### 5.3 撤单后的资金与份额

| 方向 | 处理 |
|---|---|
| 买入撤单 | `frozen_cash -= 订单金额`，`cash += 订单金额`；订单转 `cancelled` |
| 卖出撤单 | 释放该订单冻结的份额，不改动现金；订单转 `cancelled` |

- 撤单不收费用，不产生流水（或只记一条状态变更流水，用于审计）。
- 撤单与确认不会并发：确认最早在受理日 +1 个交易日 10:00，而撤单窗口在受理日 15:00 已关闭。

### 5.4 幂等与错误语义

- 幂等键：`order_id` 本身即可作为幂等标识；同一订单重复撤单返回同一结果。
- 对已撤销的订单再次撤单：返回成功（幂等 no-op），不重复退款、不重复释放份额。
- 超出撤单截止、订单已确认或已拒单：返回明确的业务错误（如 `CANCEL_WINDOW_CLOSED` / `ORDER_NOT_CANCELLABLE`），**不得静默成功**。

### 5.5 原子性

撤单必须是一个原子操作：

- 订单行锁 → 同 `user:fund` advisory 锁 → 买入时账户行锁 → 退回冻结资金 → 订单置 `cancelled`，全部在**同一个数据库事务**内完成。
- 任一步失败整体回滚，不允许出现「钱退了但订单没撤」或「订单撤了但钱没退」。
- 冻结资金不足时不部分退款，转 `manual_review` 等人工核对。
- 卖出撤单不动物资；可赎份额按「在途卖单合计」动态计算，订单转 `cancelled` 后自动恢复。
- 撤单成功后，该订单不会再被确认任务扫描到（扫描只取 `pending`）。

## 6. 确认任务执行规则

1. **触发时点**：每个交易日 `10:00`（`Asia/Shanghai`）触发一次批量确认。
2. **扫描条件**：`status = 'pending'` 且 `confirm_date <= today`，且 `now >= confirm_date 10:00`。
3. **幂等与单飞**：同一订单多次扫描只能确认一次；多实例/多 worker 下全局只允许一个批次执行（advisory lock 或等价机制）。
4. **净值未就绪**：
   - 普通基金与港股 QDII：订单保持 `pending`，在当日后续整点或下一次兜底扫描重试；不得更换净值日，不得拒单。
   - 美股 QDII：允许顺延到下一交易日 10:00 确认，并逐日顺延，直至受理日净值可用；不视为异常。
   - 任何情况下都**不得用 T-1 或 T+1 的净值顶替**。
5. **错过 10:00**（停机、异常、批次失败）：当日后续兜底扫描补确认，但**仍不得早于确认日 10:00**。
6. **确认路径不触网、不修补数据**：只读库；净值缺口由同步/修复任务解决。
7. **错误分类**：可重试错误保持 `pending`；业务拒单才落 `rejected` 并同事务补偿；具体分类沿用
   [订单确认：业务规则](../20-设计/基金与交易/订单确认-业务规则.md) §2.11。

## 7. 赎回到账规则

1. **到账日**：`settle_date = 实际确认日 + 1 个交易日`。若确认因净值未就绪而顺延，到账日同步顺延，**不允许先到账后确认**。
2. **到账时点**：到账日 `10:00` 由批量任务入账；错过时点由兜底任务补入账。
3. **确认时只生成应收**：订单进入 `settling`，不增加 `cash`；到账时 `cash += 净赎回款`，订单转 `settled`。
4. **幂等**：同一订单只能入账一次，重复任务不得重复加钱。
5. **用户侧展示**：待确认金额、在途金额（`settling`）、可用现金三者分开。
6. 到账日遇非交易日顺延到下一个交易日。

## 8. 完整时间线示例

### 8.1 普通基金，周一 14:00 买入

| 时间 | 事件 |
|---|---|
| 周一 14:00 | 下单，受理日 = 周一，冻结资金；**周一 15:00 前可撤单** |
| 周一晚间 | 周一净值同步落库 |
| 周二 10:00 | **确认**：按周一净值计算份额，解冻、建仓、写流水 |
| 周二起 | 新份额参与净值涨跌 |

### 8.2 普通基金，周一 16:00 买入

| 时间 | 事件 |
|---|---|
| 周一 16:00 | 下单，受理日 = 周二，冻结资金；**周二 15:00 前可撤单** |
| 周二 15:00 后 | 周二净值同步落库 |
| 周三 10:00 | **确认**：按周二净值计算份额 |
| 周三起 | 新份额参与净值涨跌 |

### 8.3 普通基金，周一 14:00 卖出

| 时间 | 事件 |
|---|---|
| 周一 14:00 | 下单，受理日 = 周一，份额冻结；周一享有收益；**周一 15:00 前可撤单** |
| 周二 10:00 | **确认**：按周一净值计算赎回金额，扣减份额，转 `settling` |
| 周三 10:00 | **到账**：净赎回款加入 `cash`，订单转 `settled` |

### 8.4 QDII，周一 14:00 买入

| 时间 | 事件 |
|---|---|
| 周一 14:00 | 下单，受理日 = 周一，冻结资金；**周一 15:00 前可撤单** |
| 周一晚间至周二 | 等待周一净值落库；未落库则 `pending` |
| 周三 10:00 | **确认**：按周一净值计算份额；若美股净值未到，顺延到下一交易日 |

### 8.5 QDII，周一 14:00 卖出

| 时间 | 事件 |
|---|---|
| 周一 14:00 | 下单，受理日 = 周一，份额冻结；周一享有收益；**周一 15:00 前可撤单** |
| 周二、周三 | 该笔份额不再享有收益 |
| 周三 10:00 | **确认**：按周一净值计算赎回金额，扣减份额 |
| 周四 10:00 | **到账**：净赎回款加入 `cash` |

## 9. 与改造前的差异

> 2026-11-03 已按本文完成实现：确认调度改为 10:00 主任务，卖单确认日 = T+`confirm_delay`，到账日 = 实际确认日 + 1 个交易日。下表保留改造前后的对照。

| 项 | 改造前 | 本规则要求 |
|---|---|---|
| 确认触发 | 净值同步成功即触发 + 夜间多轮兜底 | 固定每个交易日 `10:00` 触发，且不得早于 10:00 |
| 15:37 补漏任务 | 历史遗留的周一至周五 15:37 | 删除，统一为 10:00 |
| QDII | 未按基金类型区分确认延迟，也未考虑净值可得时点 | `N = 2`：美股因时差净值 T+1 晚才到，港股无时差但份额仍 T+2 登记，两者都不得在 T+1 确认 |
| 美股 QDII 净值晚到 | 无明确口径 | 允许顺延到下一交易日 10:00，逐日顺延 |
| 卖出确认延迟 | 无独立口径，实际随买入确认流程 | 与买入一致：普通 `N=1`、QDII `N=2` |
| 卖出收益归属 | 未显式定义 | 只享有成交净值日（T 日）收益 |
| 赎回到账 | `settle_date` 下单时按 `redeem_settle_delay` 算定 | 实际确认日 + 1 个交易日；确认顺延则到账顺延 |
