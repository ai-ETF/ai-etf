# 登出与注销账号功能设计文档

> 版本：v1.1
> 日期：2026-08-29
> 状态：已实现
> 前置依赖：现有注册/登录体系（`docs/用户注册功能设计文档.md`）

---

## 一、概述

### 1.1 背景

系统已具备**注册**（`POST /secure-chat/register`）与**登录**（`POST /secure-chat/login`）。签发的 access token 是**无状态 HS256 JWT**，由后端用 Supabase JWT Secret 验签（`server/auth/jwt_handler.py`）。

由此产生一个核心约束：**Supabase 无法在 access token 到期前撤销它**（supabase_auth `sign_out` 源码注释明确说明）。登录态一旦下发，攻击者拿到 token 在 1 小时内都有效，除非应用自己维护失效机制。

本设计补充两块能力：
1. **退出登录（登出）**：让当前登录态失效，用户需重新登录。
2. **注销账号**：永久删除账号并清理其全部业务数据（不可逆）。

### 1.2 目标

1. 登出后原 access token **即时失效**（应用侧黑名单）。
2. 登出同时撤销 Supabase 侧的 refresh token（服务端会话登出）。
3. 注销账号**复核密码**后再删除，防止 token 被盗后随意删号。
4. 注销时业务数据删除**原子化**（数据库函数单事务）。
5. 破坏性操作不可逆，但具备密码这一层确认。

### 1.3 现状约束

| 约束 | 说明 |
|---|---|
| access token 无状态 | HS256 自验证，Supabase 无法提前撤销 → 需要应用侧撤销清单 |
| 业务表 FK 指向 `auth.users` | chats / documents / files / messages / user_allocations / user_risk_answers / user_risk_profiles 共 6 张表，默认无级联 → 必须**先删业务数据再删账号** |
| 子表级联删除 | `document_chunks`（经 documents）、`message_chunks`（经 messages）为 `ON DELETE CASCADE` |
| files 自引用 | `files_parent_id_fkey`（无级联）→ 删除需逐层删叶子节点 |
| token 有效期 | 3600 秒（1 小时） |

## 二、核心设计决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 登出路径 | `POST /secure-chat/logout`（需 JWT） | 与注册/登录同模块，对称一致 |
| 注销路径 | `POST /secure-chat/delete-account`（需 JWT + **密码**） | 密码复核防 token 盗用删号；请求体带密码即兼作确认 |
| **注销实现** | **Postgres 函数 `public.purge_user_data(uuid)` 单事务清理 + `admin.delete_user`** | **原子性**：13 张表一次事务全删或全回滚，避免后端多次请求中途失败留孤儿数据；单次 RPC 调用 |
| access token 撤销 | 内存级黑名单 `server/auth/token_store.py`（**不持久化**） | 唯一能即时失效无状态 JWT 的方式；token 仅 1 小时有效，内存可接受；已确认暂不持久化 |
| refresh token 撤销 | `supabase.auth.admin.sign_out(token, "global")` | 服务端登出，防止该会话刷新续期 |
| 密码复核 | `sign_in_with_password(email, password)` 成功即通过 | Supabase 无独立「验证密码」接口，复用登录验证（新客户端，避免复用用户 session） |
| 删除函数授权 | 仅 `service_role` | SECURITY DEFINER 函数若授权给 authenticated，任何登录用户可调用删任意 user_id → 提权漏洞 |
| 登出幂等 | 是 | token 已失效或重复登出均返回成功 |
| 撤销清单接入点 | `get_current_user` 依赖 | 所有受保护接口统一拦截已注销 token |

> **备选方案（不采用）**：后端逐表 `DELETE`（无事务，失败留孤儿数据）；在 `auth` schema 加触发器（该 schema 由 Supabase 托管，脆弱且升级可能被覆盖）。

## 三、流程设计

### 3.1 退出登录

```
前端                        后端 (FastAPI)                      Supabase Auth
  │                            │                                   │
  ├─ POST /secure-chat/logout ─→│                                   │
  │   Authorization: Bearer t   ├─ extract_and_verify(t)：验签+查黑名单 │
  │                              ├─ admin.sign_out(t, "global") ────→│ 撤销 refresh token
  │                              ├─ revoke(t, exp)：t 加入本地黑名单   │
  │←── 200 退出登录成功 ─────────┤                                   │
```

之后携带原 token 访问任意受保护接口 → `get_current_user` 命中黑名单 → **401「令牌已注销，请重新登录」**。

### 3.2 注销账号

```
前端                        后端 (FastAPI)                      Supabase (DB/Auth)
  │                            │                                   │
  ├─ POST /secure-chat/delete-account ─→ │                          │
  │   {password} + JWT                   ├─ extract_and_verify(t)    │
  │                                       ├─ sign_in_with_password   │ ① 复核密码
  │                                       │   (email, password)      │
  │                                       ├─ rpc(purge_user_data) ───→│ ② 单事务删 13 表
  │                                       │   (新客户端, service_role)│
  │                                       ├─ admin.delete_user(id) ──→│ ③ 删 auth.users
  │                                       ├─ revoke(t, exp)           │ 当前 token 即时失效
  │←── 200 账号已注销 ────────────────────┤                          │
```

## 四、API 接口设计

### 4.1 退出登录

```
POST /api/secure-chat/logout（需 JWT）
Authorization: Bearer <access_token>
```

无请求体。

**响应 `200`：**

```json
{
  "success": true,
  "message": "退出登录成功"
}
```

> 幂等：token 已失效 / 重复登出 / token 过期，均返回成功。

### 4.2 注销账号

```
POST /api/secure-chat/delete-account（需 JWT）
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "password": "your-password"
}
```

**请求体：**

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| password | string | ✅ | 账号密码，用于复核（防止 token 被盗后随意删号） |

**响应 `200`：**

```json
{
  "success": true,
  "message": "账号已注销"
}
```

**Pydantic 模型：**

```python
class DeleteAccountRequest(BaseModel):
    """注销账号请求"""
    password: str = Field(..., description="账号密码（用于复核）")
```

## 五、数据存储设计

### 5.1 撤销清单（新增，内存，不持久化）

`server/auth/token_store.py`：`token -> exp` 的内存 dict，带线程锁。

- `revoke(token, exp)`：登出/注销时写入。
- `is_revoked(token)`：认证时查询，同时惰性清理已过期条目。

**局限（已确认接受）**：进程重启后清空，未到期的 token 恢复有效（1 小时内）。如需持久化换 Redis/DB（暂不做）。

### 5.2 业务数据清理（数据库函数，单事务）

迁移：`supabase/migrations/20260829150730_purge_user_data.sql`，完整函数如下：

```sql
CREATE OR REPLACE FUNCTION public.purge_user_data(p_user_id uuid)
RETURNS void
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
    v_deleted integer;
BEGIN
    -- 1) 会话：先 messages（级联 message_chunks），再 chats
    DELETE FROM public.messages WHERE user_id = p_user_id;
    DELETE FROM public.chats WHERE user_id = p_user_id;

    -- 2) 文档：先 documents（级联 document_chunks）；
    --    files 因自引用 parent_id（files_parent_id_fkey，无级联）需逐层删叶子节点
    DELETE FROM public.documents WHERE user_id = p_user_id;
    LOOP
        DELETE FROM public.files
        WHERE user_id = p_user_id
          AND id NOT IN (
              SELECT parent_id FROM public.files
              WHERE user_id = p_user_id AND parent_id IS NOT NULL
          );
        GET DIAGNOSTICS v_deleted = ROW_COUNT;
        EXIT WHEN v_deleted = 0;
    END LOOP;

    -- 3) 风险画像：先 profiles（fk_risk_profiles_answer 指向 answers），再 answers
    DELETE FROM public.user_risk_profiles WHERE user_id = p_user_id;
    DELETE FROM public.user_risk_answers WHERE user_id = p_user_id;

    -- 4) 其余平级表
    DELETE FROM public.user_allocations WHERE user_id = p_user_id;
    DELETE FROM public.watchlist WHERE user_id = p_user_id;
    DELETE FROM public.positions WHERE user_id = p_user_id;
    DELETE FROM public.trade_flow WHERE user_id = p_user_id;
    DELETE FROM public.trade_orders WHERE user_id = p_user_id;

    -- 5) 账户：先快照再账户（account_snapshots 可能引用 accounts）
    DELETE FROM public.account_snapshots WHERE user_id = p_user_id;
    DELETE FROM public.accounts WHERE user_id = p_user_id;
END;
$$;

GRANT EXECUTE ON FUNCTION public.purge_user_data(uuid) TO service_role;
```

**函数执行顺序**（与函数体一致，按外键安全顺序）：

| 顺序 | 表 | 说明 |
|---|---|---|
| 1 | `messages` → `chats` | messages 级联清 `message_chunks` |
| 2 | `documents` → `files` | documents 级联清 `document_chunks`；files 自引用，逐层删叶子节点 |
| 3 | `user_risk_profiles` → `user_risk_answers` | profiles 的 `answer_id` 指向 answers |
| 4 | `user_allocations` / `watchlist` / `positions` / `trade_flow` / `trade_orders` | 平级表 |
| 5 | `account_snapshots` → `accounts` | 快照可能引用账户 |

**关键点**：

- **原子性**：函数是一个 PL/pgSQL 块，所有 `DELETE` 在同一事务内，任一步失败整体回滚。
- **授权**：`GRANT EXECUTE ... TO service_role`，仅后端 service_role key 可调用（防提权）。
- **后端调用**：`admin.rpc("purge_user_data", {"p_user_id": user_id}).execute()`（新客户端，service_role 身份）。
- **不涉及**：`risk_questionnaires`（全局）、`fund_risk_profiles`（按基金）、`ai_requests`（无 user_id）等。

## 七、错误处理

| 场景 | HTTP 状态码 | message |
|---|---|---|
| 未携带 / 格式错误 token | 401 | 认证格式错误，应为 Bearer \<token\> |
| token 无效或过期 | 401 | 令牌无效或已过期 |
| token 已注销（登出后） | 401 | 令牌已注销，请重新登录 |
| 密码复核失败 | 401 | 密码错误 |
| 数据库未就绪 | 500 | 数据库连接未就绪 |
| RPC 清理业务数据失败 | 502 | 注销失败，清理用户数据时出错，请重试 |
| 删除 auth 用户失败 | 502 | 注销失败，删除账号时出错，请重试 |

## 八、安全与边界

1. **密码复核**：注销必须提交正确密码，防止 token 被盗后（凭 JWT 本身）删号。
2. **RPC 函数提权防护**：`purge_user_data` 为 SECURITY DEFINER，**仅授权 service_role**——若授权给 authenticated，任何登录用户可调用它删除任意 `user_id` 的数据（提权漏洞）。
3. **幂等登出**：登出不因 token 已失效而报错。
4. **内存黑名单局限**：进程重启后失效；已确认暂不持久化。
5. **不可逆**：注销后数据无法恢复，前端需二次确认。
6. **新增含 `user_id` 的表**：需在 `purge_user_data` 函数中同步补一条 `DELETE`（函数位于迁移文件，改动时新建修正迁移）。

## 九、测试命令

### 9.1 退出登录

```bash
API="https://ai-etf.xyz"    # 远程；本地改为 http://localhost:8000
TOKEN=$(curl -s -X POST "$API/api/secure-chat/login" \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"your-password"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

# 登出
curl -X POST "$API/api/secure-chat/logout" \
  -H "Authorization: Bearer $TOKEN"
# 预期: {"success":true,"message":"退出登录成功"}

# 验证原 token 已失效
curl -X POST "$API/api/secure-chat" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"question":"你好"}'
# 预期: 401 {"detail":"令牌已注销，请重新登录"}
```

### 9.2 注销账号（用测试账号验证，不可逆）

```bash
TOKEN=$(curl -s -X POST "$API/api/secure-chat/login" \
  -H "Content-Type: application/json" \
  -d '{"email":"test-account@example.com","password":"your-password"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

# 密码错误 → 401

  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \

# 预期: 401 {"detail":"密码错误"}

# 正常注销 → 200
```
