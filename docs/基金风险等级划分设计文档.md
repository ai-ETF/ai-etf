# 基金风险等级划分设计文档

> 版本：v1.0
> 日期：2026-08-12
> 状态：设计阶段

---

## 一、概述

### 1.1 背景

当前系统支持 10 组 ETF 联接基金（20 条 A/C 份额记录），全部为权益类产品。需要建立一套**规则透明、可复现、可争议**的风险分级体系，将基金划分为三个风险等级，用于后续交易风险提示。

### 1.2 核心原则

1. **规则透明**：每只基金的等级必须有明确的打分依据
2. **承认 ETF 本质风险**：所有 ETF 均为权益类资产，不存在"无风险"等级
3. **可扩展**：新增基金按同一套规则打分即可

### 1.3 三级分类

| 等级 | 含义 | 说明 |
|------|------|------|
| **moderate** | 中等风险 | 同类 ETF 中风险相对可控 |
| **aggressive** | 较高风险 | 具有明显的行业/风格集中风险 |
| **speculative** | 高风险 | 窄赛道、高波动，回撤风险显著 |

> 注：三个等级均属于"权益类风险"范畴。即便是 moderate 等级，也是"在 ETF 中相对中低风险"，并非绝对低风险。保守型投资者在购买任何 ETF 时都会收到风险提示。

## 二、四维评分模型

### 2.1 评分维度

每个维度 1–3 分，四个维度相加得到总分（4–12 分）。

| 维度 | 1分（风险较低） | 2分（风险中等） | 3分（风险较高） |
|------|--------------|--------------|--------------|
| **指数广度** | 宽基跨行业指数 | 单一行业指数 | 窄基主题/概念/风格 |
| **波动属性** | 大盘价值/防御型 | 消费/周期行业 | 高成长/TMT/新能源/商品 |
| **市场属性** | 纯A股 | — | QDII（跨境+汇率风险） |
| **板块特征** | 主板为主 | — | 科创板/创业板 |

> 市场属性和板块特征为二值维度（1 或 3），不存在 2 分。

### 2.2 维度定义细则

#### 指数广度

| 分数 | 判定标准 | 示例 |
|------|---------|------|
| 1 | 跟踪指数覆盖 ≥2 个行业板块、成分股 ≥100 只 | 沪深300、恒生国企指数 |
| 2 | 跟踪指数聚焦单一行业板块 | 中证银行、中证食品饮料、中证基建 |
| 3 | 跟踪指数为窄基主题/概念/风格，成分股 < 50 只 | 科创50、光伏产业、新能源车 |

#### 波动属性

| 分数 | 判定标准 | 示例 |
|------|---------|------|
| 1 | 大盘价值型/防御型板块（金融、公用事业、红利等） | 中证银行、恒生国企 |
| 2 | 消费行业/周期行业 | 食品饮料、基建工程、恒生指数 |
| 3 | 高成长/TMT/新能源/商品 | 通信设备、科创50、创业板、光伏、新能源车 |

#### 市场属性

| 分数 | 判定标准 | 示例 |
|------|---------|------|
| 1 | 纯A股市场，人民币计价 | 沪深300、创业板等 A 股指数 |
| 3 | QDII 产品，涉及跨境投资，叠加汇率风险、不同市场交易制度差异 | 恒生ETF、恒生国企（港股） |

#### 板块特征

| 分数 | 判定标准 | 示例 |
|------|---------|------|
| 1 | 成分股主要在主板上市（±10% 涨跌幅） | 沪深300、中证银行、食品饮料等 |
| 3 | 成分股主要在科创板/创业板上市（±20% 涨跌幅、散户占比高） | 科创50、创业板 |

### 2.3 总分 → 等级映射

| 总分范围 | 等级 |
|---------|------|
| 4–5 | moderate |
| 6–7 | aggressive |
| 8–12 | speculative |

## 四、技术实现

### 4.1 数据存储原则

- **维度分（四维得分）→ 存在 DB**。这是人工评估的数据，和基金名称、管理费率一样属于基金的基础属性
- **计算结果（risk_level）→ 存在 DB**。由维度分计算得出，运行时直接读，不需要每次都算
- **计算逻辑（总分→等级映射）→ 存代码**。这是全局不变的规则，不随基金变化

```
数据库（数据）              代码（逻辑）
─────────────────────      ─────────────────────
fund_fee_rules              fund_risk_scores.py
├── breadth_score           ├── DIMENSIONS        常量
├── volatility_score        ├── SCORE_THRESHOLDS  常量
├── market_score            ├── RISK_LABELS       常量
├── board_score             └── calc_risk_level() 纯函数
└── risk_level  ←──计算结果───┘
```

### 4.2 数据库变更

**新增 migration 文件：`sql/alter_fund_fee_rules_risk_level.sql`**

```sql
-- 基金四维风险评分 + 风险等级
ALTER TABLE fund_fee_rules
ADD COLUMN IF NOT EXISTS breadth_score    INT,
ADD COLUMN IF NOT EXISTS volatility_score INT,
ADD COLUMN IF NOT EXISTS market_score     INT,
ADD COLUMN IF NOT EXISTS board_score      INT,
ADD COLUMN IF NOT EXISTS risk_level       TEXT;

-- 维度分约束
ALTER TABLE fund_fee_rules
ADD CONSTRAINT chk_breadth_score    CHECK (breadth_score    IN (1, 2, 3)),
ADD CONSTRAINT chk_volatility_score CHECK (volatility_score IN (1, 2, 3)),
ADD CONSTRAINT chk_market_score     CHECK (market_score     IN (1, 3)),
ADD CONSTRAINT chk_board_score      CHECK (board_score      IN (1, 3)),
ADD CONSTRAINT chk_risk_level       CHECK (risk_level       IN ('moderate', 'aggressive', 'speculative'));

COMMENT ON COLUMN fund_fee_rules.breadth_score    IS '指数广度得分：1=宽基跨行业, 2=单一行业, 3=窄基主题';
COMMENT ON COLUMN fund_fee_rules.volatility_score IS '波动属性得分：1=大盘价值/防御, 2=消费/周期, 3=高成长/TMT/新能源';
COMMENT ON COLUMN fund_fee_rules.market_score     IS '市场属性得分：1=纯A股, 3=QDII跨境';
COMMENT ON COLUMN fund_fee_rules.board_score      IS '板块特征得分：1=主板为主, 3=科创/创业板';
COMMENT ON COLUMN fund_fee_rules.risk_level       IS '基金风险等级：moderate/aggressive/speculative';
```

### 4.3 种子数据更新

在 `sql/fund_fee_rules_seed.sql` 的每条 INSERT 中增加五个字段：`breadth_score`, `volatility_score`, `market_score`, `board_score`, `risk_level`。行值与本文第三章的打分表一致。

### 4.4 fund_risk_scores.py（纯工具模块）

模块不包含任何基金数据，只有常量定义和一个纯函数。数据全部在 DB 中。

```python
"""
基金风险等级计算（纯工具模块，不存储基金数据）

规则见 docs/基金风险等级划分设计文档.md

使用方式：
    from server.services.fund_risk_scores import calc_risk_level, get_risk_label

    level = calc_risk_level(breadth=1, volatility=1, market=1, board=1)  # "moderate"
    label = get_risk_label(level)                                         # "中等风险"
"""

# ==================== 常量 ====================

# 总分 → 等级映射
SCORE_THRESHOLDS = [
    (5, "moderate"),                     # ≤5
    (7, "aggressive"),                   # ≤7
    (float("inf"), "speculative"),       # >7
]

RISK_LABELS = {
    "moderate":    "中等风险",
    "aggressive":  "较高风险",
    "speculative": "高风险",
}


# ==================== 纯函数 ====================

def calc_risk_level(*, breadth: int, volatility: int,
                    market: int, board: int) -> str:
    """
    纯函数：四维得分 → 风险等级。

    参数:
        breadth:    指数广度 (1/2/3)
        volatility: 波动属性 (1/2/3)
        market:     市场属性 (1=纯A股, 3=QDII)
        board:      板块特征 (1=主板, 3=科创/创业)

    返回:
        risk_level: "moderate" / "aggressive" / "speculative"
    """
    total = breadth + volatility + market + board
    for threshold, level in SCORE_THRESHOLDS:
        if total <= threshold:
            return level
    return "speculative"


def get_risk_label(risk_level: str) -> str:
    """风险等级 → 中文标签"""
    return RISK_LABELS.get(risk_level, risk_level)
```

## 五、使用方式

### 5.1 运行时：读取基金风险等级

交易代码直接从 DB 读取，不做计算：

```python
rule = FundFeeService().get_fee_rule("011102")
risk_level = rule.get("risk_level")        # "speculative"
breadth = rule.get("breadth_score")        # 3（如果需要看维度分）
```

### 5.2 新增基金时

1. 按四维评分规则确定四个维度分
2. 调用 `calc_risk_level(breadth=?, volatility=?, market=?, board=?)` 确认等级
3. 在种子 SQL 中 INSERT，填入四个维度分 + risk_level
4. 完成。代码文件不用动
