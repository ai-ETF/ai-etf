## 一、概述

### 1.1 背景

用户画像系统已获取用户风险等级（conservative / moderate / aggressive），基金风险等级划分已明确（moderate / aggressive / speculative）。现在需要将两者结合，在**模拟交易（申购）时**根据用户风险偏好给出**建议性风险提示**。

### 1.2 核心原则

1. **不拦截交易**：风险提示仅作为建议性信息返回，不阻止用户执行申购操作
2. **所有 ETF 都有风险**：保守型用户购买任何 ETF 都至少收到温和提示
3. **独立返回字段**：风险提示通过独立的 `risk_warning` 字段返回，前端自行决定展示方式
4. **无画像 = 无法交易**：用户必须完成风险问卷才能获得模拟金，因此交易时画像一定存在

## 二、警告矩阵

### 2.1 用户画像 × 基金风险等级

| 用户画像 | moderate 基金 | aggressive 基金 | speculative 基金 |
|---------|:---:|:---:|:---:|
| **conservative**（保守型） | ℹ️ info | ⚠️ warning | 🔴 alert |
| **moderate**（稳健型）   | — 无提示 | ℹ️ info | ⚠️ warning |
| **aggressive**（进取型） | — 无提示 | — 无提示 | ℹ️ info |

### 2.2 三级提示说明

| 级别 | 颜色标识 | 含义 | 触发条件 |
|------|:---:|------|---------|
| `info` | ℹ️ 蓝 | 温和提示：告知风险属性差异 | 风险偏好与基金等级不完全匹配 |
| `warning` | ⚠️ 黄 | 风险警告：明确超出承受范围 | 基金等级高于画像 1 档 |
| `alert` | 🔴 红 | 强烈警告：显著不匹配 | 基金等级高于画像 2 档 |

> 举例：保守型 × speculative = 2档差距 → alert；保守型 × aggressive = 1档差距 → warning；稳健型 × speculative = 1档差距 → warning

## 三、提示消息模板

### 3.1 info（温和提示）

> ETF 均属于权益类投资产品，存在本金损失风险。该基金风险等级为 **{fund_risk_label}**，与您 **{user_risk_label}** 的风险偏好存在一定差异，请根据自身情况审慎决策。

### 3.2 warning（风险警告）

> ⚠️ 该基金风险等级为 **{fund_risk_label}**，超出您 **{user_risk_label}** 的风险承受范围。建议：① 控制该基金配置比例不超过总资产的 **{suggested_pct}%**；② 结合自身投资期限和回撤承受能力综合评估。

### 3.3 alert（强烈警告）

> 🔴 该基金为 **{fund_risk_label}** 品种，与您 **{user_risk_label}** 的风险偏好存在显著差异。强烈建议：① 重新评估是否配置此类高风险产品；② 如确需配置，建议比例不超过 **{suggested_pct}%**；③ 做好承受较大回撤的准备。

### 3.4 建议配置比例

| 用户画像 | moderate 基金 | aggressive 基金 | speculative 基金 |
|---------|:---:|:---:|:---:|
| **保守型** | — | ≤ 10% | ≤ 5% |
| **稳健型** | — | — | ≤ 15% |
| **进取型** | — | — | — (无上限) |

> 建议比例指**单只基金占总投资组合的市值比重**，当前阶段作为提示文字中的参考值，不做硬性校验。
>
> 实现约定：`suggested_max_pct` 仅出现在 **warning/alert** 级提示中（info 消息模板无比例占位符，仅表达风险差异）；info 级该字段返回 `null`。

## 四、API 设计

### 4.1 申购响应新增 risk_warning 字段

**POST /api/portfolio/apply-purchase**

现有响应结构新增 `risk_warning` 字段：

```json
{
  "success": true,
  "message": "申购申请已提交（当日受理），将于 2026-08-13 确认份额（T+1），资金已冻结",
  "data": {
    "fund_code": "011102",
    "fund_name": "天弘中证光伏ETF联接A",
    "amount": 10000.00,
    "price": 1.2345,
    "fee": 12.00,
    "net_amount": 9988.00,
    "confirm_date": "2026-08-13",
    "cash_remaining": 89990.00,
    "frozen_cash": 10000.00,
    "status": "pending",
    "trade_time": "2026-08-12T10:30:00+08:00"
  },
  "risk_warning": {
    "level": "alert",
    "fund_risk_level": "speculative",
    "fund_risk_label": "高风险",
    "user_risk_level": "conservative",
    "user_risk_label": "保守型",
    "message": "🔴 该基金为高风险品种，与您保守型的风险偏好存在显著差异...",
    "suggested_max_pct": 5
  }
}
```

**无风险提示时**：

```json
{
  "success": true,
  "message": "...",
  "data": { ... },
  "risk_warning": null
}
```

### 4.2 risk_warning 字段定义

| 字段 | 类型 | 说明 |
|------|------|------|
| level | string | 提示级别：`info` / `warning` / `alert` |
| fund_risk_level | string | 基金风险等级：`moderate` / `aggressive` / `speculative` |
| fund_risk_label | string | 基金风险等级中文标签 |
| user_risk_level | string | 用户风险等级：`conservative` / `moderate` / `aggressive` |
| user_risk_label | string | 用户风险等级中文标签 |
| message | string | 完整的风险提示文字（含换行符和 emoji） |
| suggested_max_pct | int | 建议的该基金最大配置比例（百分比） |

### 5.2 核心逻辑流程

```
apply_purchase(user_id, fund_code, amount, ...)
  │
  ├─ 0. 校验基金白名单 + ETF 拦截（现有）
  ├─ 1. 计算确认日（现有）
  ├─ 2. 校验最低申购金额（现有）
  ├─ 3. 获取净值（现有）
  ├─ 4. 计算申购费（现有）
  ├─ 5. 获取基金名称（现有）
  │
  ├─ 5a. 生成风险提示 ← 新增步骤
  │     ├─ FundRiskService.get_risk_profile(fund_code)
  │     │     ├─ 查 fund_risk_profiles 表（risk_level + risk_label 均入库）
  │     │     └─ 查不到（基金未分级）→ 跳过风险检查，risk_warning=null
  │     ├─ RiskService.get_latest_profile(user_id) → 取画像 risk_level + risk_label（均入库）
  │     ├─ 用户画像或基金等级任一缺失 → 跳过风险检查，risk_warning=null
  │     ├─ 查警告矩阵 → 得到 level（info / warning / alert）
  │     ├─ warning/alert 级再查 SUGGESTED_PCT_MATRIX → 建议比例 suggested_pct
  │     ├─ 构建 message（填入 fund_risk_label, user_risk_label, suggested_pct）
  │     └─ 组装 RiskWarning 对象
  │
  ├─ 6. 校验可用现金（现有）
  └─ 7. 冻结资金 + 写订单 + 返回（现有，在返回的 response 中附带 risk_warning）
```

### 5.3 risk_service.py 新增方法

新增静态方法 `RiskService.get_risk_warning(user_risk_level, user_risk_label, fund_risk_level, fund_risk_label)`，作为风险提示生成的唯一入口：

- 入参为两侧的风险等级与中文标签（运行时均从各自表直接读取，不做计算）
- 内部由辅助函数 `_build_risk_warning` 完成：查 `RISK_WARNING_MATRIX` 警告矩阵得到级别（info / warning / alert）；warning/alert 级再查 `SUGGESTED_PCT_MATRIX` 取建议比例；最后经 `_build_warning_message` 拼接完整文案
- 返回 `risk_warning` dict，无对应组合时返回 `None`（无需提示）

### 5.4 schemas.py 新增模型

```python
class RiskWarning(BaseModel):
    """交易风险提示"""
    level: str          # info / warning / alert
    fund_risk_level: str
    fund_risk_label: str
    user_risk_level: str
    user_risk_label: str
    message: str
    suggested_max_pct: Optional[int] = None  # 仅 warning/alert 携带（info 模板无比例占位符）
```

### 5.5 portfolio_service.py 改动示意

在 `apply_purchase()` 中，步骤 5（获取基金名称）之后、校验可用现金之前，调用私有方法 `_get_risk_warning(user_id, fund_code)`：

- 内部依次读取用户画像（`RiskService.get_latest_profile`）与基金风险等级（`FundRiskService.get_risk_profile`），两者任一缺失即返回 `None`
- 两者齐全则调用 `RiskService.get_risk_warning` 组装提示
- 整个流程由 `try/except` 包裹，任何异常仅打 warning 日志并返回 `None`，**不影响交易**
- 生成的 `risk_warning` 随申购响应顶层返回（无提示时为 `null`）

### 5.6 异常处理

风险检查的任何异常都不应影响交易执行。采用防御性编码：
- `try/except` 包裹整个风险检查逻辑
- 异常时 `risk_warning = None`，交易正常进行
- 打 warning 级别日志供排查
