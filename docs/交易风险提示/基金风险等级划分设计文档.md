# 基金风险等级划分设计文档

> 版本：v1.1
> 日期：2026-08-22
> 状态：已实现

---

## 一、概述

### 1.1 背景

当前系统支持 10 组 ETF 联接基金（20 条 A/C 份额记录），全部为权益类产品。需要建立一套**规则透明、可复现、可争议**的风险分级体系，将基金划分为三个风险等级，用于后续交易风险提示。

### 1.2 核心原则

1. **规则透明**：每只基金的等级必须有明确的打分依据
2. **承认 ETF 本质风险**：所有 ETF 均为权益类资产，不存在"无风险"等级
3. **可扩展**：新增基金按同一套规则打分即可

### 1.3 三级分类

| 等级 | 含义 | 说明 |
|------|------|------|
| **moderate** | 中等风险 | 同类 ETF 中风险相对可控 |
| **aggressive** | 较高风险 | 具有明显的行业/风格集中风险 |
| **speculative** | 高风险 | 窄赛道、高波动，回撤风险显著 |

> 注：三个等级均属于"权益类风险"范畴。即便是 moderate 等级，也是"在 ETF 中相对中低风险"，并非绝对低风险。保守型投资者在购买任何 ETF 时都会收到风险提示。

## 二、四维评分模型

### 2.1 评分维度

每个维度 1–3 分，四个维度相加得到总分（4–12 分）。

| 维度 | 1分（风险较低） | 2分（风险中等） | 3分（风险较高） |
|------|--------------|--------------|--------------|
| **指数广度** | 宽基跨行业指数 | 单一行业指数 | 窄基主题/概念/风格 |
| **波动属性** | 大盘价值/防御型 | 消费/周期行业 | 高成长/TMT/新能源/商品 |
| **市场属性** | 纯A股 | — | QDII（跨境+汇率风险） |
| **板块特征** | 主板为主 | — | 科创板/创业板 |

> 市场属性和板块特征为二值维度（1 或 3），不存在 2 分。

### 2.2 维度定义细则

#### 指数广度

| 分数 | 判定标准 | 示例 |
|------|---------|------|
| 1 | 跟踪指数覆盖 ≥2 个行业板块、成分股 ≥100 只 | 沪深300、恒生国企指数 |
| 2 | 跟踪指数聚焦单一行业板块 | 中证银行、中证食品饮料、中证基建 |
| 3 | 跟踪指数为窄基主题/概念/风格，成分股 < 50 只 | 科创50、光伏产业、新能源车 |

#### 波动属性

| 分数 | 判定标准 | 示例 |
|------|---------|------|
| 1 | 大盘价值型/防御型板块（金融、公用事业、红利等） | 中证银行、恒生国企 |
| 2 | 消费行业/周期行业 | 食品饮料、基建工程、恒生指数 |
| 3 | 高成长/TMT/新能源/商品 | 通信设备、科创50、创业板、光伏、新能源车 |

#### 市场属性

| 分数 | 判定标准 | 示例 |
|------|---------|------|
| 1 | 纯A股市场，人民币计价 | 沪深300、创业板等 A 股指数 |
| 3 | QDII 产品，涉及跨境投资，叠加汇率风险、不同市场交易制度差异 | 恒生ETF、恒生国企（港股） |

#### 板块特征

| 分数 | 判定标准 | 示例 |
|------|---------|------|
| 1 | 成分股主要在主板上市（±10% 涨跌幅） | 沪深300、中证银行、食品饮料等 |
| 3 | 成分股主要在科创板/创业板上市（±20% 涨跌幅、散户占比高） | 科创50、创业板 |

### 2.3 总分 → 等级映射

| 总分范围 | 等级 |
|---------|------|
| 4–5 | moderate |
| 6–7 | aggressive |
| 8–12 | speculative |

## 四、技术实现

### 4.1 数据存储原则

- **维度分（四维得分）→ 存在 DB**。这是人工评估的数据，属于基金的基础属性
- **计算结果（risk_level）→ 存在 DB**。由维度分计算得出，运行时直接读，不需要每次都算
- **中文标签（risk_label）→ 存在 DB**。用户侧/基金侧均入库，运行时直接读，不映射计算
- **计算逻辑（总分→等级映射）→ 存代码**。这是全局不变的规则，不随基金变化

```
数据库（数据）                   代码（逻辑）
─────────────────────           ─────────────────────
fund_risk_profiles（独立表）      fund_risk_scores.py
├── breadth_score                ├── DIMENSIONS        常量
├── volatility_score             ├── SCORE_THRESHOLDS  常量
├── market_score                 ├── RISK_LABELS       常量
├── board_score                  └── calc_risk_level() 纯函数
├── risk_level  ←──计算结果───┘
└── risk_label   （中文标签，直接入库）
```

> 解耦说明：基金风险评分**独立建表** `fund_risk_profiles`，不与 `fund_fee_rules`（费率规则）混合。`fund_code` 唯一关联；表中不冗余基金名称，名称由模拟交易服务按 `fund_code` 从费率规则侧单独获取（不做 join）。

### 4.2 数据库变更 ✅ 已完成

**迁移文件：`supabase/migrations/20260821155107_create_fund_risk_profiles.sql`**

```sql
CREATE TABLE public.fund_risk_profiles (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  fund_code varchar(10) NOT NULL UNIQUE,
  breadth_score int NOT NULL CHECK (breadth_score IN (1, 2, 3)),
  volatility_score int NOT NULL CHECK (volatility_score IN (1, 2, 3)),
  market_score int NOT NULL CHECK (market_score IN (1, 3)),
  board_score int NOT NULL CHECK (board_score IN (1, 3)),
  risk_level text NOT NULL CHECK (risk_level IN ('moderate', 'aggressive', 'speculative')),
  risk_label text NOT NULL,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);
```

### 4.3 种子数据更新 ✅ 已完成

20 条种子数据随建表迁移一并写入（`INSERT ... ON CONFLICT (fund_code) DO UPDATE`，幂等）。行值与本文第三章的打分表一致，`risk_label` 按映射直接写死（moderate→中等风险 / aggressive→较高风险 / speculative→高风险）。

### 4.4 fund_risk_scores.py（纯工具模块）✅ 已存在

纯工具模块，**不包含任何基金数据**（数据全部存在 `fund_risk_profiles` 表），只提供常量与纯函数。作用与流程如下：

- `SCORE_THRESHOLDS`：总分 → 等级阈值表（`≤5` → moderate，`≤7` → aggressive，`>7` → speculative）
- `RISK_LABELS` / `USER_RISK_LABELS`：基金/用户风险等级 → 中文标签映射
- `calc_risk_level(breadth, volatility, market, board)`：纯函数，将四维得分求和后按阈值表映射出风险等级，无任何副作用
- `get_risk_label(level)` / `get_user_risk_label(level)`：中文标签查询工具

> 运行约定：`risk_level → 中文标签` 已随 `risk_label` 入库，运行时从 `fund_risk_profiles.risk_label` / `user_risk_profiles.risk_label` **直接读取，不做计算**；`calc_risk_level()` 仅在新基金入库时用于确认等级。

## 五、使用方式

### 5.1 运行时：读取基金风险等级

交易代码从 `fund_risk_profiles` 独立表直接读取，不做计算：

```python
from server.services.fund_risk_service import FundRiskService

fund_risk = FundRiskService().get_risk_profile("011102")
risk_level = fund_risk["risk_level"]     # "speculative"
risk_label = fund_risk["risk_label"]     # "高风险"
breadth = fund_risk["breadth_score"]     # 3（如果需要看维度分）
```

### 5.2 新增基金时

1. 按四维评分规则确定四个维度分
2. 调用 `calc_risk_level(breadth=?, volatility=?, market=?, board=?)` 确认等级
3. 按 4.3 方式在 `fund_risk_profiles` 中 INSERT（或新建迁移），填入四个维度分 + `risk_level` + `risk_label`
4. 完成。代码文件不用动
