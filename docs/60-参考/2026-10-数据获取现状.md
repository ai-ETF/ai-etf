## 1. 全景：六个数据面

| # | 数据面 | 主要获取方式 | 落地形态 |
|---|---|---|---|
| 1 | 场内行情（快照 / K线 / 分时） | akshare → 新浪 | 类级内存 + 文件缓存，**不落库** |
| 2 | 场外基金目录（白名单 / 费率 / 风险画像） | akshare + 自建 requests → 东财 | **Supabase（持久）** |
| 3 | 净值序列（场内 ETF 与场外基金**共用**） | akshare → 东财 | **无缓存、无落库，直通** |
| 4 | 组合与交易（持仓估值 / 货基收益 / 订单确认） | akshare + 自建 urllib → 东财 | Supabase |
| 5 | 交易日历 | akshare → 新浪 | 模块级内存（按天） |
| 6 | AI 与文档（问答 / 检索 / 上传） | Anthropic + 本地 embedding | Supabase |

**两条上游厂商的分界**（这一点解释了很多历史现象）：

- **场内**走东财 `push2*` 集群 / 新浪 `hq.sinajs.cn` 系；
- **场外与净值**走东财 `fund.eastmoney.com` / `fundf10.eastmoney.com` / `fundmobapi.eastmoney.com` / `api.fund.eastmoney.com`。

2026-07-28 ~ 2026-10-13 的故障中，**只有 `push2*` 被拒**，`fund.eastmoney.com` 全程正常——所以那段时间 `/detail` 活着、其它行情端点全空。

## 2. 场内行情线（`/api/market/*`）

### 2.1 端点与取数方式

端点定义见 `server/api/market/`（`__init__.py` 挂 `/market` 前缀）：

`spot/{code}`、`spot/name/{n}`、`ranking`、`search`、`filter`、`categories`、`category/{c}`、`money-flow/{code}`、`money-flow/name/{n}`、`money-flow/ranking`、`kline/{code}`、`kline/name/{n}`、`intraday/{code}`、`intraday/name/{n}`、`detail/{code}`、`detail/name/{n}`、`health`。

| 端点 | 取数方式 | 上游接口 | 上游域名 | 缓存 |
|---|---|---|---|---|
| `spot/*`、`ranking`、`search`、`filter`、`categories`、`category/*`、`money-flow/*` | **只读内存表** `_spot_dict` | `ak.fund_etf_category_sina(symbol="ETF基金")` | `vip.stock.finance.sina.com.cn` | 类级内存，30s |
| `kline/{code}` | 先读文件缓存，未命中才出网 | `ak.fund_etf_hist_sina(symbol="sh/sz"+code)` | `finance.sina.com.cn` | `/tmp/etf_kline_cache/{code}_{period}_sina.json`，**1 天** |
| `intraday/{code}` | **每次出网** | `ak.stock_zh_a_minute(symbol=..., period='1')` | `finance.sina.com.cn` / `quotes.sina.cn` | **无** |
| `detail/{code}` | 内存 spot + **2 次净值出网** + 1 次概览出网 | 见 §4 | 见 §4 | **无** |
| `health` | 硬编码 `{"status":"ok"}` | — | — | — |

实测：`fund_etf_category_sina("ETF基金")` → **1696 行 / 5.1s / 单请求**；`stock_zh_a_minute` → **1970 根滚动窗口，跨 9 天**（所以分时**必须按当日过滤**，否则会把十几天画成一天）。

### 2.2 刷新机制

`server/services/spot_cache_scheduler.py:105`：

- `IntervalTrigger(seconds=30)` → `FinanceApiService.refresh_spot_cache()`
- 交易时段判定：`trading_calendar.is_trading_time()`（§6）
- 启动时另有 `_warmup_cache()` 拉一次（`spot_cache_scheduler.py:23`）

### 2.3 `refresh_spot_cache()` 的实际逻辑

`server/services/finance_api_service.py:1285`：

1. **退避优先**：`if time.time() < cls._next_retry_at: return False`（不发请求）
2. **非交易时段跳过**：`if not is_trading_time(beijing_now()) and cls._spot_dict is not None: return True`
   → ⚠️ 这个条件**要求缓存非空**。若从未成功过（重启后、或上游一直挂），非交易时段**仍会每 30 秒出网**（见 §11 P3）
3. **成功**：`_rebuild_spot_dict(df)`；`_consecutive_failures = 0`；`_next_retry_at = 0`
4. **失败**：`_consecutive_failures += 1`；`backoff = min(30 × 2^(n-1), 1800)` 秒；**保留旧缓存不覆盖**

失败计数 `_consecutive_failures` 与 `_next_retry_at` 是**类属性、全局一份**，不区分端点（见 §11 P10）。

### 2.4 代码起点（commit `e711ecb`）

三个接口由东财换成新浪：

| 用途 | 换前 | 换后 |
|---|---|---|
| 全市场快照 | `ak.fund_etf_spot_em()`（push2delay，17 请求） | `ak.fund_etf_category_sina(symbol="ETF基金")`（1 请求） |
| 日K | `ak.fund_etf_hist_em(period=...)`（push2his） | `ak.fund_etf_hist_sina(symbol=...)`（周/月线改由日线重采样） |
| 分时 | `ak.fund_etf_hist_min_em(period="1")`（push2his） | `ak.stock_zh_a_minute(symbol=..., period='1')` |

### 2.5 换源带来的字段与口径差异（实测）

| 项 | 东财 | 新浪 |
|---|---|---|
| 快照列数 | 37 列（含 换手率 / 量比 / 委比 / 外盘内盘 / 主力净流入 / 份额 / 市值 / 现手 / 买一卖一 / 数据日期 / 更新时间） | 13 列 |
| 新浪缺的字段 | — | `turnover_rate`、`volume_ratio`、`outer_vol`、`inner_vol`、`order_ratio`、`main_inflow*`、`latest_shares`、`float_mv`、`total_mv` → 代码里**恒填 `0.0`**（`finance_api_service.py:414-431`）；`amplitude` 由 `(high-low)/prev_close` 还原；`data_date` 取请求时的北京日期；`update_time` 为空串 |
| **成交量单位** | **手**（512890 实测 `3608627`） | **份**（实测 `360862713`）——**差 100 倍** |
| 成交额 | 442962540 | 442962540（一致） |
| 日K 是否含当日 | 含（盘中最后一根是今天，未收盘） | 不含（盘中最后一根是昨天） |

## 3. 场外基金目录线（白名单 / 费率 / 风险画像）

- **触发**：定时任务每天 **02:17**（`spot_cache_scheduler.py:141`，`misfire_grace_time=7200`）；手动入口 `python -m server.scripts.sync_fund_catalog`
- **互斥**：`flock` 锁文件 `/tmp/fund_catalog_sync.lock`（环境变量 `FUND_SYNC_LOCK_PATH` 可覆盖）；CLI 与定时任务共用；拿不到锁则跳过本轮（不视为失败）
- **发现候选**（`fund_catalog_sync.py:230` `_discover_by_name`）：
  - `ak.fund_name_em()` → **实测 28049 行 / 12.1s**
  - 筛选规则 `is_off_exchange_linked_fund`（`fund_catalog_sync.py:105`）：名称含「联接」 ∩（含 ETF 或基金类型为指数型）∩ 不含 货币/债券/定开/封闭/持有期
  - → **实测 2290 只**候选
- **逐只抓两个上游**（`server/services/fund_fee_source.py`，`HEADERS` = UA `Mozilla/5.0` + `Referer: https://fundf10.eastmoney.com/`，`TIMEOUT = 15`，**无重试**）：
  - `https://fundf10.eastmoney.com/jjfl_{code}.html` —— HTML，解析申购费分档 / 赎回费分档 / 管理费 / 托管费 / 销售服务费 / 申购起点 / 交易状态
  - `https://fundmobapi.eastmoney.com/FundMNewApi/FundMNBasicInformation?FCODE={code}&deviceid=1&plat=Iphone&product=EFund&version=1` —— JSON，取 简称 / 类型 / 跟踪指数 / 单日申购上限
- **节奏**：`DEFAULT_REQUEST_INTERVAL = 0.3` 秒 → 2290 × 2 ≈ **4580 请求**，光 `sleep` 就 ≈ 11.5 分钟；文档记的实际总耗时 **20-30 分钟**（`spot_cache_scheduler.py:68`）
- **落库**：`fund_fee_rules`（upsert，`UPSERT_BATCH_SIZE = 50`）+ `fund_risk_profiles`
- **失败语义**：单只失败不影响其余；**关键字段缺失的基金不写入白名单**——因为 `fund_fee_rules` 是交易准入的唯一依据（查不到即拒绝交易）。全量重抓，**无增量判断**（见 §11 P5）
- **注意**：**这条线不抓净值**。
- **下游读取**：`/api/portfolio/funds`、`/api/portfolio/funds/{fund_code}` 只读这两张表（`server/api/off_exchange_funds.py`）

## 4. 净值线（场内 ETF 与场外基金共用）

**关键事实**：净值**不分场内场外，走同一个接口**。`finance_api_service.py:646` 明确记录了选型理由——`fund_open_fund_info_em` 按 `symbol` 查询，**场内场外均可用（110020 / 512890 实测）**，且走 `fund.eastmoney.com`（生产可达）；旧接口 `fund_etf_fund_info_em` 已因上游表结构变更（akshare 1.18.64 下抛 `Length mismatch: Expected axis has 14 elements, new values have 13 elements`）弃用。

### 4.1 调用点

| 调用点 | 接口 | 参数 | 缓存 |
|---|---|---|---|
| `_query_nav_history` `finance_api_service.py:659` | `ak.fund_open_fund_info_em` | `indicator="单位净值走势"` | **无** |
| `_query_accumulated_nav` `finance_api_service.py:691` | `ak.fund_open_fund_info_em` | `indicator="累计净值走势"` | **无** |
| `_query_nav` `finance_api_service.py:215` | `ak.fund_open_fund_info_em` | 单位净值 | **无** |
| `PortfolioService._get_nav` `portfolio_service.py:257` | `ak.fund_open_fund_info_em` | 单位净值 | **无** |

上游域名：`fund.eastmoney.com`。

### 4.2 访问放大（这是全项目最需要留意的一处）

- `GET /api/market/detail/{code}`（`server/api/market/detail.py:31`）→ `query_detail`（`finance_api_service.py:554`）：
  1. `_query_detail_overview` → 1 次 `ak.fund_overview_em`
  2. 内存 `_spot_dict` 取 `realtime`（不出网）
  3. `_query_nav_history` → **2 次出网**（单位净值走势 + 累计净值走势）
  → **每次访问 3 次出网**，且无缓存。

- `PortfolioService._get_nav` 有 4 个调用点（`portfolio_service.py:628`、`941`、`1216`、`1347`），其中 **`:941` 位于持仓循环内**：
  → `GET /api/portfolio/positions`、`/account`、`/daily-returns` **每个持仓 × 每次请求**各出网一次，**无缓存**。

- 且 `fund_open_fund_info_em` 返回的是**该基金全量历史**（老基金可达数千条），不是增量——每次调用都下载整条序列，再 `tail(limit)`。

**净值线没有缓存、没有落库、没有失败计数、没有熔断。**

## 5. 组合与交易线

- **持仓估值** → 见 §4（直通净值，无缓存）
- **货基万份收益**（`portfolio_service.py:297`；同一接口 `f10/lsjz` 对普通基金也可用，见 §12）：直连
  `https://api.fund.eastmoney.com/f10/lsjz?fundCode={code}&pageIndex=1&pageSize=5`（`urllib.request` + `Referer: https://fundf10.eastmoney.com/`，`timeout=10`）；
  **按北京日期内存缓存**（当天多次调用不重复请求）；
  接口失败 / 返回空 / 字段缺失 → **抛 `RuntimeError`，不做任何兜底**（「宁可当天不入账，也不用虚假数字污染累计收益」）
- **货基净值特例**：`MONEY_FUND_CODE` 净值恒 `1.0000`，代码内直接返回，不查上游（`portfolio_service.py:244`）
- **调度**：货基收益入账 每天 **00:05**（`spot_cache_scheduler.py:128`）；pending 订单确认 **15:37（mon-fri）**（`:115`）；启动时另做一次 pending 补偿（`:88`）

## 6. 交易日历

`server/services/trading_calendar.py`（全项目唯一来源）：

- 上游：`ak.tool_trade_date_hist_sina()`（新浪），**按北京日期缓存在模块级 `_cache`**，一天最多请求一次
- 抓取失败：**沿用上一次成功的副本**，且**不更新日期**（下次调用会重试）
- **从未成功过**：退化为「周一至周五即交易日」
- `PortfolioService._is_trading_day()` 只是委托它的一层薄封装（多处调用 + 多处测试打桩，是 T 日口径的稳定接缝）

## 8. 缓存全景

| 数据 | 载体 | TTL | 失效方式 |
|---|---|---|---|
| 场内快照 | 类级内存 `_spot_dict` | 30s | 定时任务覆盖 |
| 基金名单（名称 ↔ 代码） | 类级内存 `_fund_list_cache` | 1 小时 | 到期重取 |
| K 线 | 文件 `/tmp/etf_kline_cache` | 1 天 | mtime |
| **分时** | — | **无** | — |
| **历史净值** | — | **无** | — |
| **概览 / 费率（akshare 路径）** | — | **无** | — |
| 货基万份收益 | 类级内存 `_money_fund_cache` | 当天 | 日期变更 |
| 交易日历 | 模块级内存 `_cache` | 当天 | 日期变更 |
| 场外目录（费率 / 风险） | Supabase | 持久 | 每天 02:17 全量覆盖 |
| Spot 失败退避 | 类级 `_next_retry_at` / `_consecutive_failures` | 30s → 30min | 成功即清零 |

## 9. 调度全景

| 任务 | 触发 | 频率 | 出网量 / 日 |
|---|---|---|---|
| 行情快照刷新 | `IntervalTrigger(seconds=30)` | 交易时段每 30s（480 次/日） | 480 请求（新浪单请求）\* |

## 11. 已发现的问题点

| # | 位置 | 现象 |
|---|---|---|
| P1 | `portfolio_service.py:941` + `finance_api_service.py:659,691` | 净值线**无缓存无落库**；`/portfolio/positions` 逐持仓调 `_get_nav` → 随用户量线性放大 |
| P2 | `finance_api_service.py:1090` | 分时**无缓存**，每次请求都出网 |
| P3 | `finance_api_service.py:1302` | 非交易时段跳过要求 `_spot_dict is not None`，缓存为空时会**全天候 30s 出网** |
| P4 | akshare 新浪系函数（`fund_etf_category_sina` / `fund_etf_hist_sina` / `stock_zh_a_minute`）与两个批量净值函数（`fund_open_fund_daily_em` / `fund_etf_fund_daily_em`） | **无 timeout、无重试**（裸 `requests.get`）；东财 `push2*` 系有 `timeout=15` + 3 次重试 |
| P5 | `fund_catalog_sync.py:326` | 2290 只**全量重抓**（≈4580 请求/日），无增量判断 |
| P6 | `server/api/market/__init__.py:26` | `/api/market/health` 恒返回 `{"status":"ok"}` |
| P7 | `money_flow.py:23` vs `:60` | `/money-flow/ranking` 被 `/money-flow/{fund_code}` 抢先匹配，**该接口从未可用过** |
| P8 | `fund_etf_category_sina` vs `fund_etf_spot_em` | 两源**字段数量与成交量单位都不同**（13 列 vs 37 列；份 vs 手，差 100 倍） |
| P9 | Supabase schema | `market_indicators` 表存在但**代码中零引用** |
| P10 | `finance_api_service.py:45-47` | 失败计数 / 退避是**类属性、全项目一份**（`_consecutive_failures`、`_next_retry_at`），不按端点区分。目前只有 spot 有冷却，K线/分时完全没有；**一旦给它们补冷却而沿用同一份状态，任意端点的失败就会把其它端点一起拖入冷却** |
