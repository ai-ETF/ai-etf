# 对外数据源请求与返回实测

> **这份文档回答一个问题**：项目对外的每一次请求，究竟打到了哪个域名、拿到的是什么东西。
>
> **怎么来的**：不是抄文档、不是看 akshare 源码推断，而是**逐个源真打一次**，记录 HTTP 状态码、Content-Type、响应字节数、耗时和**原始返回样本**；再用 akshare / 项目自身的解析函数跑一遍，记录**解析后的字段结构与样本行**。探针脚本在 `/tmp/upstream-probe/probe.py`（仓库外，只读、每源 1 次请求）。
>
> **时效**：采样时间 2026-10-13 盘后（20:30–21:00）。上游会改版——**样本里的数字会变，字段名和布局是决策依据**。若某天字段对不上，先重跑探针脚本再下结论。
>
> **与另一份文档的分工**：[`2026-10-数据获取现状.md`](./2026-10-数据获取现状.md) 讲「项目**怎么用**这些数据」（调用链、缓存、调度、请求量），本文讲「上游**吐出来的是什么**」。设计取舍见 [`行情数据源.md`](../20-设计/行情/行情数据源.md)。
>
> **注意**：本文不包含任何密钥。文中出现的 `ut=`、`deviceid=1` 等是上游公开的固定参数，不是我们的凭据。

## 1. A 类：项目当前在用

### A1 · 新浪全市场 ETF 快照 —— 榜单/列表的源头

```
https://vip.stock.finance.sina.com.cn/quotes_service/api/jsonp.php/
  IO.XSRV2.CallbackList['h5_uf7QN3jsq9sK7lZu']/Market_Center.getHQNodeData
  ?page=1&num=5000&sort=symbol&asc=1&node=etf_hq_fund&symbol=&_s_r_a=page
```

- **调用方**：`ak.fund_etf_category_sina(symbol="ETF基金")` → `FinanceApiService.refresh_spot_cache()`，每 30s 轮询。
- **请求头**：`Referer: https://finance.sina.com.cn/`。
- **实测**：`200` / `0.45s` / `application/javascript; charset=gbk` / **37,639 bytes**。
- **返回样本**（JSONP，外面套一层回调）：

```
/*<script>location.href='//sina.com';</script>*/
IO.XSRV2.CallbackList['h5_uf7QN3jsq9sK7lZu']([
 {"symbol":"sh510010","code":"510010","name":"180治理ETF交银",
  "trade":"1.741","pricechange":0,"changepercent":0,
  "buy":"1.735","sell":"1.747","settlement":"1.741",
  "open":"1.739","high":"1.747","low":"1.730",
  "volume":102700,"amount":179231,"ticktime":"15:00:01",
  "per":0,"pb":0,"mktcap":23072.4914242,"nmc":22201.99804,"turnoverratio":0.08053},
 …]
```

- **上游原始字段（20 个）**：`symbol` `code` `name` `trade` `pricechange` `changepercent` `buy` `sell` `settlement` `open` `high` `low` `volume` `amount` `ticktime` `per` `pb` `mktcap` `nmc` `turnoverratio`
- **akshare 解析后**：`(1696, 13)` 列 = `代码 名称 最新价 涨跌额 涨跌幅 买入 卖出 昨收 今开 最高 最低 成交量 成交额`
- **⚠️ 这里有一个重要发现**：akshare **丢掉了 6 个字段** —— `ticktime` `per` `pb` `mktcap` `nmc` `turnoverratio`。也就是说，
  **新浪快照其实是带 换手率 / 总市值 / 流通市值 / 市盈率 / 市净率 的**（见 `turnoverratio:0.08053`、`mktcap:23072.49`、`nmc:22201.99`），
  只是 akshare 没把它放进 DataFrame。详见 §5.2 —— 这一条直接动摇了设计文档里「新浪缺换手率/市值」的论据。

### A4 · 新浪分钟线 —— 分时的源头

```
https://quotes.sina.cn/cn/api/jsonp_v2.php/var%20_sh512890_1_1=/CN_MarketDataService.getKLineData
  ?symbol=sh512890&scale=1&ma=no&datalen=1970
```
- **调用方**：`ak.stock_zh_a_minute(symbol="sh512890", period="1")`，**无缓存**。
- **实测**：`200` / `0.34s` / `application/javascript; charset=gbk` / **260,467 bytes**。
- **返回样本**：

```
var _sh512890_1_1=([{"day":"2026-09-23 13:53:00","open":"1.183","high":"1.183","low":"1.182",
                    "close":"1.183","volume":"418500","amount":"494767.2119"}, …])
```

- **akshare 解析后**：`(1970, 7)` 列 `day open high low close volume amount`
  - 首行 `2026-09-23 13:53:00`，末行 `2026-10-13 15:00:00` —— **约 8 个交易日的滚动窗口**（`datalen=1970` 是请求上限，不是「当日」）。
  - 起点落在 13:53 而不是 09:30，说明它是**按根数向前截断**，需要自己按日期切出「当日」。
- **单位**：`volume` 单位是**份**。
- **注意**：**不含均价**（可选 `ma=no` → 无均线），分时均线要自己按 `amount/volume` 累积算。

- **实测**：`200` / `0.20s` / `application/json` / **99 bytes**：

### A11 · 东财历史净值（货基万份收益）

```
https://api.fund.eastmoney.com/f10/lsjz?fundCode=000198&pageIndex=1&pageSize=5
```
- **调用方**：`PortfolioService._money_fund_per10k_income()`（`MONEY_FUND_CODE = "000198"`），按天缓存，**失败不兜底**。

```json
{"Data":{"LSJZList":[
```

## 5. 实测得出的关键事实（决策直接用）

### 5.1 成交量单位：东财 = 手，新浪/腾讯 = 份（实测坐实）

同一天、同一只 `512890`（2026-10-13）：

| 源 | 原始值 | 换算为份 |
|---|---|---|
| 东财 B2 `klines` 第 6 字段 | `7,477,753` | ×100 = `747,775,300` |
| 新浪 A1 快照 `volume` | `747,775,307` | 已是份 |
| 新浪 A3 日K `volume` | `747,775,307` | 已是份 |
| 腾讯 D2 `6` 字段 | `7,477,753` | ×100 = `747,775,300` |
| 东财 B1 快照 `f5` | 手 | ×100 |

成交额三方**完全一致**：`917,070,768`。→ 差的确实只是量的口径。

**结论**：设计文档定的「统一为**份**」是对的，且实现时 **新浪/腾讯原样通过，东财 ×100**。

### 5.2 ⚠️ 新浪快照其实带 换手率/市值 —— 是 akshare 把它丢了

设计文档里「配置 C 把列表分给东财」的理由之一是*新浪缺换手率/市值*。**实测不支持这个理由**：

- 新浪 A1 **上游原始响应**里明确有 5 个指标字段：`turnoverratio`（换手率）、`mktcap`（总市值）、`nmc`（流通市值）、`per`（市盈率）、`pb`（市净率）。
- akshare 的 `fund_etf_category_sina()` **只取了 13 列**，把这 5 个连同 `ticktime` 一起**丢弃**。
- **含义**：这不构成换源障碍——**我方的适配器完全可以直接解析 A1 的 JSONP 原文**，拿到 akshare 不肯给的那 5 个字段，**不必为此改用东财**。

**这一条需要单独决策**：配置 C 的分源理由需要重新表述（或者调整方案）。除本项外，配置 C 的其他论据（分时新浪原生可用、东财分时被拒过）不受影响。

| 接口 | 行数 | 触发请求数 | 耗时实测 | 内容 | 是否含历史 |

| 源 | 编码 | 必要请求头 |

| 新浪 A1 / A4 / D1 | `gbk` / `GB18030` | **`Referer: https://finance.sina.com.cn/`**（D1 无 Referer 实测 **403**） |
| 新浪 A2 / A3 | — | 同上 |

### 5.6 失败形态多样，不能只看 HTTP 状态码

| 形态 | 实例 | 后果 |
|---|---|---|
| `403 Forbidden` | D1 无 Referer | 请求层失败，好识别 |
| **`200` + 空数据** | A7 → `{"Data":null,"ErrCode":4}` | **静默失败**，最容易漏 |
| 延迟剧变 | C1：1.22s ↔ 31.5s（同一天两次采样） | 无 timeout 会挂住线程 |
| 混淆/压缩文本 | A2（508B 日期表）、A3（21KB 全历史 K 线） | 格式一变，解码全废 |
| HTML 表格改版 | A8 / A9 | 表格错位 → 字段串位 |

### 5.7 数据新鲜度：不同源「今天」的定义不一样

同一时刻（2026-10-13 盘后）实测上次净值日期：

| 源 | 最新净值日期 |
|---|---|
| A6 场内 `512890` | **2026-10-12**（场内净值 T+1 出） |
| A6 场外 `110020` | **2026-10-13**（当日已出） |
| C1 场外全市场 | **2026-10-13** |
| C2 场内全市场 | **2026-10-13**（即 512890 在 C2 里可能已有当日，而 A6 没有） |

→ **同一天的净值，场外当晚有、场内当晚没有**；且 `A6` 与 `C2` 对同一只场内基金的新鲜度可能不同。若做「净值落库 + 兜底」，**必须记录数据本身带的日期，不能假设「今天拉的 = 今天的净值」**。
