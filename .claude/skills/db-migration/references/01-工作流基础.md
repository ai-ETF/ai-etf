# 数据库迁移工作流（Supabase CLI）

> 本文档为 skill 内副本，源文件：`docs/数据库迁移工作流.md`

本项目使用 **Supabase CLI 迁移机制**管理数据库结构变更，替代了此前的 `sql/` 目录手工脚本。
所有旧 SQL 文件已归档至 [docs/legacy_sql/](../../docs/legacy_sql/)（只读参考，不再用于变更数据库）。

> 方案设计详见 [引入Supabase-Migration机制方案.md](../../docs/引入Supabase-Migration机制方案.md)
>
> 日常开发按场景查：[02-日常场景操作手册.md](02-日常场景操作手册.md)

## 环境要求

- **Supabase CLI**：迁移命令的前置依赖。安装与升级：`supabase --version`
- **Docker**：仅 `supabase db pull` / `db diff` / `db dump` 需要（shadow 数据库）。`db push` / `query` / `link` / `migration repair` / `migration fetch` / `migration new` **不需要**。
  - 若当前 shell 会话的 `docker` 权限组尚未生效，用 `sg docker -c "<命令>"` 包裹 docker 依赖的命令。
- **远端数据库**：已通过 `supabase link --project-ref wiynpkkfsiiqnofhifhs` 关联。

## 迁移文件目录与历史

- 迁移目录：`supabase/migrations/`，文件名 `{时间戳}_{描述}.sql`
- 迁移历史表：`supabase_migrations.schema_migrations`（记录已应用的迁移版本）
- 基线迁移：`20260819113859_remote_schema.sql`，由 `supabase db pull` 从远端完整导出
  （6 个扩展、2 个枚举、20 张表、索引、RLS 策略、8 个函数、触发器、注释与默认权限）。
  本迁移是一次性基线，**请勿改动**；后续变更一律新增迁移文件。

## 日常流程

### 1. 修改数据库结构（推荐做法）

**方式 A — 手动编写（结构变更，推荐）：**

```bash
supabase migration new <描述>
# 编辑生成的 supabase/migrations/{时间戳}_{描述}.sql，写入 CREATE / ALTER / DROP 语句
```

**方式 B — 从远端反向生成（把已手动执行的 SQL 变成迁移）：**

```bash
# 生成 ALTER 语句（需要 Docker）
supabase db diff --linked --use-migra -f <描述>

# 或导出当前远端 schema 全文（需要 Docker）
supabase db pull --linked --schema public --diff-engine migra
```

> 若 diff 结果中包含与远端完全一致的 CHECK 约束重建、函数重建等噪音（migra 对部分 CHECK 表达式、
> CRLF 换行的函数体比较不准），属正常现象，并非真实漂移，手工核对后剔除即可。

### 2. 应用迁移到远端

```bash
supabase db push --linked
```

会把本地 `supabase/migrations/` 中尚未应用的迁移按顺序执行，并记录到远端历史表。
（部分 CLI 版本可能将 Docker 权限告警输出为 catalog 缓存失败，若最后出现 `Finished supabase db push.` 即为成功。）

> 注：`supabase migration push` 不存在，应用迁移的入口是 `supabase db push`。

### 3. 检查迁移状态

```bash
supabase migration list --linked
```

`Local │ Deployed` 两列应对齐。

### 4. 处理历史不一致

若本地与远端历史表错位（如误删迁移文件、远端被手工修改），先用 `supabase migration repair`：

```bash
# 将某个迁移标记为已回滚（本地不再认为它已应用）
supabase migration repair --status reverted <版本> --linked
```

> 基线建立时曾用此方式将两笔废弃的旧迁移历史（`0001`、`20260121054728`）标记为 reverted。

## 本地临时命令

- 直接查询/执行 SQL：`supabase db query --linked "SELECT 1"`
- 导出数据（仅含数据，不含结构）：`supabase db dump --linked --data-only`

## 已废弃的机制

- **`_run_sql.py`**（仓库根目录）：旧的手工 SQL 执行脚本（依赖 pg-meta），已由迁移流程取代，**勿再使用**。
- **`sql/` 目录**：全部归档至 `docs/legacy_sql/`。
- 应用运行时通过 Supabase Python 客户端（`.from(...)` / `.rpc(...)`）访问数据库，不使用 ORM；
  数据库结构由迁移管理，代码只读数据与调用 RPC（如 `match_chunks` / `match_chunks_fts`）。

## 注意

- 不要直接在 `supabase/migrations/` 基线文件上做增量修改；新增迁移文件才可追溯。
- `supabase/.temp/`、`supabase/.branches/` 为 CLI 本地状态，不提交到 Git。
