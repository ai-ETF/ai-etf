# 输入契约：关系模型 Markdown

这份文档定义 skill 能读懂的关系模型格式。**它描述的是关系模型（表、字段、键），不是 E-R 图，也不是建表 SQL。**

一份合格的关系模型至少要能回答：有哪些表、每张表有哪些字段、主键是什么、哪一列指向哪张表的哪一列。

## 必需的章节

解析器按 `## 数字.` 切分章节，所以编号和标题要保留：

| 章节 | 作用 | 缺失后果 |
|---|---|---|
| 头部统计 | 用于交叉校验 | 跳过统计校验 |
| `## 1. 业务分域` | 表 → 域归属，页面分页依据 | 所有表都会报“没有归入任何业务域” |
| `## 2. 关系（表）` | 表、字段、主键、外键 | 没有表可画 |
| `## 5. 关系总表` | 真实外键 / 逻辑引用清单 | 图上没有连线 |

`## 3. 视图`、`## 4. 枚举类型` 可选。

## 头部统计

必须写成一行，数字与正文一致：

```markdown
> **统计**：30 表 / 312 列 / 31 外键 / 7 逻辑引用 / 1 视图 / 2 枚举。
```

校验器会重新统计正文，不一致直接报错。这样能挡住“改了表却忘了改统计”。

## 1. 业务分域

```markdown
## 1. 业务分域

| 编号 | 域 | 说明 | 包含关系 |
|---|---|---|---|
| 01 | 用户 | 用户身份、关注列表与资产配置模板。 | `auth.users`、`watchlist`、`allocation_models`、`user_allocations` |
```

- 表名放在反引号里，用 `、` 分隔。
- 每张表必须且只能出现在一个域里。
- 域的 `说明` 会显示在页面总览卡片上。

## 2. 关系（表）

### 2.1 域标题与表标题

```markdown
## 2. 关系（表）

### 域 01 · 用户

#### `watchlist`（用户自选列表）
```

- `### 域 NN · 名称` 必须与第 1 节的编号、名称一致。
- `#### \`表名\`（中文名）` 的中文名可省略；它是卡片标题下的说明。
- 外部实体的写法固定为：

```markdown
#### `auth.users`（外部实体）

- 主键：`id`
- 属性：本文件只登记被引用的 `id uuid`，其余列不属于本设计范围。
```

“外部实体”会被识别为 `external_table`，不参与表/列计数。

### 2.2 表的元信息行

顺序不限，但标签必须完全一致：

```markdown
- 说明：用户自选列表；user_id + fund_code 组成复合唯一约束。
- 主键：`id`
- 候选键（主键之外）：`user_id` + `fund_code`；`user_id`（部分唯一：WHERE (is_active = true)）
- 外键：`user_id` → `auth.users(id)` ON DELETE CASCADE
- 逻辑引用：`fund_code` ⇢ `fund(fund_code)`（fund 1 — N watchlist；无数据库外键）
```

规则：

- **主键**：多个主键列写成 `` `a`, `b` ``。
- **候选键**：多个候选键用 `；` 分隔；一个候选键内部的列用 ` + ` 连接。部分唯一索引在括号里写 `部分唯一：<谓词>`。
- **外键**：真实外键，数据库里必须存在约束。格式是 `` `列` → `表(列)` ``，可跟 `ON DELETE CASCADE|RESTRICT|SET NULL|NO ACTION`。多个外键用 `；` 分隔。
- **逻辑引用**：没有数据库约束、按命名或业务规则建立的关联。格式是 `` `列` ⇢ `表(列)`（原因） ``。它不会让字段获得 FK 标记，但会画成虚线。
- 没有内容时写 `—`，不要留空。

### 2.3 字段表

```markdown
| 列名 | 类型 | 约束 |
|---|---|---|
| `id` | `uuid` | PK, NOT NULL |
| `user_id` | `uuid` | FK→auth.users.id ON DELETE CASCADE, NOT NULL |
| `fund_code` | `character varying(10)` | UNIQUE, NOT NULL |
| `fund_name` | `character varying(100)` | NULL |
```

- 表头固定为 `| 列名 | 类型 | 约束 |`。
- 约束用 `, ` 分隔，取值：`PK`、`UNIQUE`、`NOT NULL`、`NULL`、`FK→表.列`，可带 `ON DELETE X`。
- 类型写 PostgreSQL 规范名（`character varying(10)`、`numeric(18,2)`、`timestamp with time zone`），不要写成 `varchar` 简写——页面会原样显示。
- 默认值不写在这里：它属于展示信息，从已有 HTML 继承，避免 md 频繁变动。

## 3. 视图（可选）

```markdown
## 3. 视图

### `fund_catalog`

- 类型：`view`（security_invoker=true）
- 派生自：`fund` JOIN `fund_trade_rule`
- 说明：仅包含 lifecycle_status='active' 的基金。

| 列名 | 类型 | 约束 |
|---|---|---|
| `fund_code` | `character varying(10)` | NULL |
```

## 4. 枚举类型（可选）

```markdown
## 4. 枚举类型

| 枚举名 | 取值 |
|---|---|
| `risk_level` | conservative、moderate、aggressive |
```

## 5. 关系总表

**这一节是连线的权威来源。** 第 2 节表内的「外键」行只用来给字段打 `FK` 标记；真正的边从这里读。

```markdown
## 5. 关系总表

| # | 类型 | 从关系.属性 | 主关系.属性 | 基数 | 删除规则 | 约束名 / 说明 |
|---|---|---|---|---|---|---|
| 1 | 真实外键 | `documents.file_id` | `files.id` | N:1 | CASCADE | documents_file_id_fkey |
| 2 | 逻辑引用 | `fund_nav.fund_code` | `fund.fund_code` | N:1 | — | 净值表有意不建 FK，由函数内校验 |
```

- `类型` 只能是 `真实外键` 或 `逻辑引用`。
- 复合外键写成 `` `position_lots.user_id, fund_code` ``。
- 带 schema 的表名 `auth.users.id` 也能解析（按最后一个点切分表名和列名）。
- `删除规则` 没有时写 `—`。
- 真实外键的最后一列填**约束名**；逻辑引用填**原因说明**。

## 不属于本文件的内容

RLS 策略、索引明细、函数、触发器、迁移历史都不要写进来。它们不参与 E-R 图，写进来只会让解析器多一层噪音。需要保留这些信息时，让 `database-inventory.md` 之类的盘点文档承担。

## 常见写错

| 现象 | 原因 |
|---|---|
| 校验报“主键不在字段表里” | 主键行有，字段表漏了这一列 |
| 校验报“目标表不存在” | 外键写了一个没定义的表名，或拼写不一致 |
| 校验报“没有归入任何业务域” | 新表没加进第 1 节的域节点清单 |
| 图上少一条边 | 第 5 节漏了这条关系 |
| 字段被标成 FK 但图上没有边 | 表内有「外键」行，但第 5 节没写 |
